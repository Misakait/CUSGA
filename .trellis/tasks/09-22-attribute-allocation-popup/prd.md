# 属性加点界面与分配入口

## Goal

在背包属性栏的等级行右侧新增「分配」按钮（有剩余属性点时显示），点击打开加点弹窗；弹窗内先累计加点，点确认才一次性写入，支持撤回。

## Requirements

- R1 在背包属性栏「等级 x」的同一行右侧新增「分配」按钮。
- R2 该按钮仅在属性组件存在且 `AvailablePoints > 0` 时显示，点数为 0 时隐藏。
- R3 点击按钮打开背包内加点弹窗（与既有「详情」弹窗同一种 `PopupPanel` 模式）。
- R4 弹窗内先累计加点；点「确认」才一次性写入属性，点「取消」或关闭弹窗则放弃。
- R5 弹窗每项只显示「属性名 + 当前值」两列，不显示已投入点数与每点成长。
- R6 弹窗顶部显示当前可用点数。
- R7 已累计的点可以逐点撤回（每行同时提供加与减）。
- R8 写入必须走属性组件既有接口 `TryAllocatePoint`，UI 不直接改属性字段，也不自行计算属性规则。

## Acceptance Criteria

- [ ] AC1 有可用点时「分配」按钮可见；可用点数归零后按钮立即隐藏，再次获得点数后立即出现。
- [ ] AC2 点击「分配」弹出加点弹窗，并显示当前可用点数。
- [ ] AC3 弹窗中物攻、物防、法强、法抗、速度各占一行，每行显示该属性当前值。
- [ ] AC4 点「+1」只增加弹窗内的累计量并显示加点后的预计值；此时属性组件的可用点数与属性值都不得变化。
- [ ] AC5 累计总量不得超过可用点数：达到上限时所有「+1」禁用。
- [ ] AC6 点「确认」后每项累计按 `TryAllocatePoint(类型, 累计数)` 一次性写入，可用点数按累计总量扣减，弹窗关闭且累计清零。
- [ ] AC7 点「取消」或直接关闭弹窗时，不写入任何点数，累计清零，属性值与可用点数保持原样。
- [ ] AC8 属性组件缺失时「分配」按钮隐藏，且不产生任何报错或异常。
- [ ] AC9 弹窗打开期间可用点数被外部改变（例如又升了一级）时，以最新点数为准重新限制累计上限；累计量超过最新可用点数时拒绝确认并刷新显示。

## Notes

- 非目标：不做洗点/重置已分配点数，不做数量输入框或长按连加，不改动 AttributeComponent 的任何属性规则。
- `GrowthPerPoint` 只用于弹窗里的预计值显示，不参与任何写入计算。
