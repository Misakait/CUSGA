# 实施清单与交付边界

用户已审阅最新架构并明确授权实施，以下范围已经实施，Godot 编辑器验证由主代理统一执行。保留清单用于核对交付，当前待人工审阅及提交许可；任务状态维持 in_progress，不自动提交、推送或归档。

1. 沿用已确认的指定资源规则，资格列表保持为空。明确本期剩余的满仓、主动退出和时间口径；正式资源内容、换算和建筑转移规则不提前编造。
2. 用户审阅最终方案后，准备实施和检查的规范上下文。
3. 确认 Godot MCP 连接 CUSGA，重新检查 Git 状态、用户改动、存档初始化顺序与关联文档。
4. 建立数据对象、固定结果和规则配置，兼容旧钱包、升级接口及存档键。收获容量默认 5，保留局外容量变更接口和未来建筑选择接口，本期不实现升级或建筑玩法。
5. 接入 SaveManager 测试门禁和局内暂缓写入，覆盖带入、自动保存、战斗请求、退出和快照模式。
6. 接入 SettlementManager 开局、统计、死亡与通关，解决重复事件和战斗收尾竞争；成功拾取不得自动带出普通资源。在 Inspector 配置死亡测试奖励开关，死亡结果生成前赠送 1 个测试资源，每局只生成一次。
7. 默认生成 5 个结算格子，包括空格，接入容量读取与刷新、set_description 和 add_description、两个独立按钮脚本和新局导航。
8. 同步模块文档、规范及 docs/游戏机制与玩法内容.md，规划不能提前写成当前玩法。
9. Godot MCP 验证：editor_state 或 session_manage(list)，filesystem_manage(scan)，聚焦 test_run，Settlement 和 Main 冒烟，logs_read(game)、game_eval 和截图；结束只 project_manage(stop)，不关闭编辑器。
10. 使用独立测试存档验证主档、备份、临时档和写入计数，覆盖拾取、带入、战斗、测试结算、自动保存及退出，不破坏真实存档。
11. 验证正式保存读回、旧档兼容、已结束旧局不可恢复、重复事件、重复点击、保存失败重试和容量边界。追加描述不覆盖原文；默认 5 格；测试赠送关闭时死亡无收获，开启时仅死亡生成 1 个测试物品，通关不赠送；重复面板加载和保存重试不赠送第二次；未来建筑接口不得绕过资格检查。
12. 重查 Git 状态，只保留任务改动，保护已有 agent.local.md。提交或推送先逐文件报告并等待明确同意。

## 风险与回退边界

- 写入门禁先于收益入账接入，否则测试收益可能被自动保存捕获。
- 同一余额、等级和存档键只能有一个数据来源及有效参与者。
- 结算必须阻止旧异步战斗回调恢复输入。
- 文档要求 SaveManager 首个启动，但 project.godot 当前排列不同；实施前核实，不在规划阶段调整。
- 若需新增领取界面、更改存档结构或改动无关玩法，先明确新增范围再实施。
