# 执行顺序

1. 搜索脚本路径、全局类名、导出字段、动态调用和场景资源引用，记录用户已有编辑。
2. 实现注册类名、精确的导出类型和中文字段说明；最小迁移必要的资源数组声明与测试夹具。
3. 更新地形物资配置说明、机制文档入口和资源规范。
4. 编辑器 filesystem_manage scan；验证类注册及导出类型，执行地形配置与布局、采集行为聚焦测试。
5. 通过真实场景 game_eval 加载地图及资源并调用生成器，检查日志，停止游戏，保持编辑器打开。
6. Trellis check 审核；最终重新核对 git status 与差异，报告使用步骤及验证结果。未经用户同意不运行提交或会自动提交的归档脚本。
