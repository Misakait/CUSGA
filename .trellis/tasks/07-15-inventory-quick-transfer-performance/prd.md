# 优化背包快捷移动性能

## Goal

消除玩家背包与出战卡组之间 Shift/Alt 快捷移动产生的重复整表绑定和容量变化时的整组槽位重建，并阻止已经隐藏的合成界面继续响应背包变化执行无效刷新，降低单次与批量移动的主线程开销，同时保持物品移动、堆叠、排序、卡组扩容、拖拽、提示框和合成界面重新打开后的内容行为不变。

## Background

- `InventoryComponent.MoveItemFrom` 在一次跨背包移动后分别通知来源与目标背包，导致两个 UI 网格各刷新一次（`entities/components/InventoryComponent.cs:608-646`）。
- `InventoryUI` 的背包和卡组变更处理都会遍历全部槽位并调用 `SlotUI.Bind`（`core/ui/InventoryUI.cs:211-267`）。
- `SlotUI.Bind` 每次都会解除并重新连接 `ItemStack.OnStackChanged`，随后立即刷新视觉（`core/ui/SlotUI.cs:65-81`）。
- `InventoryUI.GenerateSlots` 会释放并重新实例化整个网格；当视图数量与容量不一致时会调用它（`core/ui/InventoryUI.cs:192-249`）。
- 出战卡组会保留尾部空槽并在填满时扩容，因此卡组已满后的连续加入可能反复触发整组重建（`entities/components/BattleDeckComponent.cs:17-49`、`entities/components/InventoryComponent.cs:122-143`）。
- Alt 批量移动逐堆叠调用单次移动，因此当前会按移动堆叠数重复发送来源与目标通知（`entities/components/InventoryComponent.cs:567-593`）。
- 详情提示使用共享 `TooltipPanel`；它不是每次移动都重新创建，只有指针所在槽位刷新时才更新或隐藏（`core/ui/SlotUI.cs:233-265`、`core/ui/ItemTooltipPresenter.cs:13-45`）。
- `CraftingUI` 首次绑定后会持续订阅玩家背包；`Close` 仅隐藏节点，因此隐藏期间仍会刷新所选配方、重新计算可合成数量并重建材料行（`core/ui/crafting/CraftingUI.cs:70-105`、`core/ui/crafting/CraftingUI.cs:285-291`）。

## Requirements

### R1. 保持快捷移动行为

- Shift 点击仍只移动当前物品堆叠；技能卡在玩家背包和出战卡组之间双向移动，非技能卡仍走现有装备逻辑。
- Alt 点击仍批量移动全部符合条件的技能卡。
- 不允许用不同物品替换目标槽位，堆叠、剩余数量和失败返回语义保持不变。

### R2. 避免普通移动的无效重新绑定

- 当槽位索引、背包引用和 `ItemStack` 引用没有变化时，不得重复解除/连接 `OnStackChanged`。
- 普通跨背包移动应依靠现有 `ItemStack.OnStackChanged` 更新实际变化的槽位。
- 排序或其他导致 `_slots` 中 `ItemStack` 引用换位的操作仍必须使 UI 重新绑定到正确引用。

### R3. 增量同步槽位结构

- 背包或卡组容量增加时，只创建缺少的 `SlotUI`，不得释放并重建仍然有效的槽位节点。
- 首次绑定、切换到不同背包以及潜在容量减少场景仍要得到正确且无残留订阅的 UI 结构。

### R4. 合并批量移动通知

- Alt 批量移动期间可以逐个修改 `ItemStack`，但来源与目标背包的全局变更通知应分别合并到批次结束时发送。
- 单次移动仍保持来源与目标各一次通知，避免改变现有订阅者的可观察语义。
- 批处理中途无法移动的堆叠不得产生虚假成功数量或多余通知。
- 调用方提供的筛选条件必须在第一次迁移前完成求值；若筛选抛出异常，来源和目标背包都不得留下本方法造成的部分迁移。

### R5. 保持提示框与信号生命周期正确

- 快捷移动后不得显示已经移走物品的陈旧提示内容。
- 不得产生重复 `OnStackChanged` 订阅；槽位退出树或改绑时必须解除旧订阅。
- 共享提示框实例和现有鼠标进入/离开行为保持不变。

### R6. 回归验证

- 为单次与批量快捷移动补充聚焦回归测试，覆盖移动结果、通知次数、卡组扩容和尾部空槽。
- 验证普通背包固定容量、排序后 UI 引用同步、拖拽移动和装备快捷移动没有行为回归。
- 使用项目规定的 `CI=true` 构建，并对背包 UI 所在 Godot 场景执行必要的 headless 运行验证。

### R7. 停止隐藏合成界面的后台刷新

- `CraftingUI` 隐藏期间不得因玩家背包 `InventoryChanged` 而刷新所选配方、重新计算数量或重建材料行。
- 重新打开 `CraftingUI`，或仅恢复隐藏它的父级 `CanvasLayer` 时，必须基于当前背包状态执行一次完整同步，不能显示隐藏期间遗留的数量、按钮状态或材料清单。
- 重复打开、关闭或改绑 `CraftingComponent` 不得产生重复订阅或遗漏解除订阅。
- 保持当前配方选择、合成按钮逻辑、数量边界和合成结果提示语义不变。

## Acceptance Criteria

- [x] AC1：默认容量未变化时，成功的 Shift 跨背包移动不会释放或重新实例化已有 `SlotUI`。
- [x] AC2：普通移动中，未换位的槽位不会重复解除/连接 `OnStackChanged`，来源和目标槽位视觉仍立即正确。
- [x] AC3：出战卡组容量从 C 增加到 C+K 时只新增 K 个槽位视图，已有 C 个视图保持实例不变。
- [x] AC4：Alt 批量移动 N 个物品堆叠时，来源与目标 `InventoryChanged` 各触发一次，而不是各 N 次。
- [x] AC5：Shift 单次移动仍使来源与目标 `InventoryChanged` 各触发一次。
- [x] AC6：技能卡双向移动、批量筛选、堆叠合并、尾部空槽、普通背包固定容量和排序行为通过回归测试。
- [x] AC7：移动后提示框不显示陈旧内容，且不存在重复槽位事件订阅。
- [x] AC8：`env CI=true dotnet build CUSGA.sln --no-restore` 通过；相关 C# 测试与 Godot headless 场景验证无阻塞错误。
- [x] AC9：`CraftingUI` 关闭后，背包变化不会调用配方刷新或创建/释放材料行节点。
- [x] AC10：隐藏期间背包发生变化后重新打开 `CraftingUI`，可合成数量、材料拥有量、数量输入和按钮状态均与当前库存一致。
- [x] AC11：多次打开/关闭/改绑合成组件后，每个有效背包最多保留一个 `CraftingUI` 订阅，退出树时没有残留订阅。
- [x] AC12：批量筛选条件抛出异常时，来源和目标背包保持调用前状态，且不会出现未通知的部分迁移。
- [x] AC13：持久 Godot 回归用例覆盖槽位实例复用、卡组增量扩容、排序改绑、隐藏期间不刷新和父级恢复后的补刷新。

## Constraints

- 不改变玩家可见的快捷键、移动规则、卡组容量规则或拖拽交互。
- 不引入新的全局单例、第三方框架或与本问题无关的 UI 重构。
- 新增或修改的公共 C# API必须包含中文 XML 文档；复杂批处理逻辑使用中文注释解释原因。

## Out Of Scope

- 重新设计物品数据模型或将 `ItemStack` 改为不可变对象。
- 修改提示框的视觉样式、动画或显示延迟。
- 优化与快捷移动调用链无关的战斗卡牌 UI。
- 全面重构所有隐藏 UI 的订阅生命周期；本任务只明确修复 `CraftingUI`，仓库仅接受共享槽位同步改进带来的收益。
