# 玩家等级与经验值系统

## Goal

为游戏新增一套角色等级与经验值系统：等级从 1 级起步、上限 50 级，采用线性经验曲线；对外提供「获得经验」与「升级」两类稳定接口；每次升级发放属性点，交由玩家自行分配；并在背包角色属性栏的第一行显示当前等级。

本任务的定位是**铺设数值骨架与接口**，不接入任何具体玩法（战斗、采集、任务均不发放经验），由后续任务调用接口。

## Requirements

### R1 等级与经验规则

- 等级取值范围为 `1..50`，初始等级为 1，初始经验为 0。
- 从等级 `L` 升到 `L+1` 所需经验为 `100 + 50 * (L - 1)`。
  - 1→2 需 100，2→3 需 150，3→4 需 200，依次递增 50。
  - 49→50 需 2500。从 1 级练到 50 级累计需 63700 点经验。
- 经验累积达到阈值时**自动升级**；单次获得的经验允许**连续升多级**。
- 达到 50 级（满级）后不再累积经验，获得经验接口返回 0。

### R2 对外接口

必须提供以下稳定接口（PascalCase 命名，与项目现有 autoload 风格一致）：

| 接口 | 职责 |
| --- | --- |
| `AddExperience(amount) -> int` | 获得经验；返回本次实际入账的经验值，并自动结算升级 |
| `TryLevelUp() -> bool` | 消耗当前经验提升 1 级；经验不足或已满级时返回 false |
| `AddLevels(count) -> int` | 直接提升指定级数、不消耗经验；返回实际提升级数 |
| `GetLevel() -> int` | 读取当前等级 |
| `GetExperience() -> int` | 读取当前等级内的已累积经验 |
| `GetExperienceToNextLevel() -> int` | 读取升到下一级所需经验；满级返回 0 |
| `IsMaxLevel() -> bool` | 判断是否满级 |
| `ClaimPendingAttributePoints() -> int` | 领取挂起的属性点并清零 |

并对外声明信号：等级变化、经验变化、属性点发放。

### R3 升级产出：属性点

- 每提升 1 级发放固定点数（默认 3 点/级），从 1 级练满共 147 点。
- 属性点通过玩家 `AttributeComponent` 的既有 `EarnPoints` 接口进入属性系统，由玩家使用 `TryAllocatePoint` 自行分配。
- 等级系统**不直接修改任何属性数值**，属性的最终成长完全由玩家分配决定。
- 当玩家实体尚未存在（或已离开场景）时，已发放的点数必须**挂起不丢失**，待玩家就绪后领取。

### R4 界面显示

- 在背包的角色属性栏（`AttributeSummaryUI`）**第一行**显示当前等级，位于「物攻」之上。
- 显示格式为标签「等级」+ 数值（例如 `等级    1`），**不显示**经验进度。
- 等级变化时界面实时刷新。
- 等级系统不可用时（例如独立运行不含该 autoload 的测试场景）该行显示占位符 `-`，不得报错。

### R5 持久化

- 沿用项目当前的开发期策略：不跨运行保存（与 `PlayerWallet`、`PlayerProgression` 的 `PersistAcrossRuns` 保持同值 false）。
- 存档协议预留：分组 `player`，键 `level` 与 `experience`。
- 仅持久化等级与经验；属性点属于「已发放且已由玩家持有」的数据，随属性组件走，不重复存档。

### R6 范围与约束

- **不修改** `AttributeComponent` 的属性计算、钳制与重算逻辑。
- **不接入**任何玩法发放经验；不修改怪物、战斗、采集、时间等系统。
- 新增系统必须是**独立可复用组件**，不硬编码引用玩家实体路径。

## Acceptance Criteria

- [ ] 新 autoload `PlayerLevel` 已在 `project.godot` 注册，启动时无 `SCRIPT ERROR`。
- [ ] 等级初始为 1；`AddExperience(99)` 后等级仍为 1、经验为 99；再 `AddExperience(1)` 后等级为 2、经验为 0。
- [ ] 单次 `AddExperience(1050)` 能从 1 级连续升到 6 级（100+150+200+250+300 = 1000 消耗，余 50）。
- [ ] `GetExperienceToNextLevel()` 在 1 级返回 100、2 级返回 150、49 级返回 2500、50 级返回 0。
- [ ] 等级达到 50 后 `AddExperience` 返回 0，等级与经验不再变化。
- [ ] `TryLevelUp()` 在经验不足时返回 false 且不改数值；经验足够时返回 true 并正确扣除经验。
- [ ] `AddLevels(3)` 返回值与实际提升级数一致；满级时返回 0。
- [ ] 每次升级发放 3 点属性点，且点数可通过 `ClaimPendingAttributePoints()` 领取，重复领取返回 0。
- [ ] 玩家实体存在时，升级后 `AttributeComponent.AvailablePoints` 实际增加，且提升的属性进入最终属性值。
- [ ] 背包属性栏第一行显示当前等级；等级变化后文本立即更新；无等级系统时显示 `-`。
- [ ] 退出场景树后，玩家实体与属性栏都不再保留失效的等级信号连接。
- [ ] `test_run(suite="player_level_contract")` 与 `test_run(suite="attribute_summary_ui_contract")` 全部通过。
- [ ] 运行主场景无 `SCRIPT ERROR`，属性栏截图可见等级行。
- [ ] `docs/游戏机制与玩法内容.md` 已同步等级、经验曲线与属性点数值。

## Notes

- 本次已与开发者确认的四项决策：①升级只发属性点、由玩家自行分配；②只做接口、不接任何玩法；③属性栏只显示等级数字、不显示经验进度；④上限 50、线性曲线 `100 + 50*(L-1)`。
- 「每级发放属性点数」为本次选定的默认值 3，属可调参数，实现时提取为脚本顶部常量。
- 项目内不存在既有的角色等级成长系统：`PlayerProgression` 只管仓库容量/带入栏的付费升级，`StartingStats` 的 `*Growth` 字段语义为「属性点投入成长」（由 `attribute_value.gd` 的 `GrowthPerPoint` 消费），与角色等级无关。因此本系统是新建系统，而非续接既有等级逻辑。
- `AttributeComponent.EarnPoints` 此前没有任何生产调用方，本系统是它的第一个真实来源。
