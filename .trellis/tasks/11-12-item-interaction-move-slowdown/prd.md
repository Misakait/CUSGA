# 物品交互时移动速度降低80%

## Goal

玩家与世界物品进行持续交互时，移动速度降低 80%（保留基础速度的 20%）；交互结束、取消或失效后立即恢复正常速度。

## Requirements

- 触发范围：棋盘地形卡的持续长按交互，即采集、破坏等会进入 `InteractionRange` 长按流程的世界物品交互。
- 速度口径：键盘行走与鼠标点击行走都使用同一个“有效行走速度”，交互期间为 `PlayerData.walk_speed × 0.2`。
- 减速倍率必须可配置：在玩家 Inspector 中导出，默认 `0.2`，允许 0～1，便于后续调整。
- 进入长按后立即减速；长按完成、提前松开、走出范围、目标失效、切换目标、场景卸载、重复回调等所有清理路径都必须且只能恢复一次。
- 不改变长按是否继续的判定：交互范围内移动仍不打断长按，只是移动变慢；键盘行走仍照常生效。
- 不扩大到其它系统：建筑 F 使用/拆除、地图方向长按、掉落物自动拾取、背包/合成/仓库等 UI 交互不减速；不修改行动值、采集耗时、伤害或存档格式。
- 同一时刻只允许一个世界物品长按；减速状态是玩家节点的运行时状态，不写入 `PlayerData.tres` 或存档。

## Acceptance Criteria

- [ ] `PlayerChar` 提供公共的有效速度查询与开始/结束物品交互接口；未交互时等于 `walk_speed`，交互时为 `walk_speed × 0.2`。
- [ ] 键盘移动 `PlayerChar.move_player` 与鼠标移动 `ClickWalk.physics_update` 都使用有效速度，不存在只减速其中一条路径。
- [ ] `WorldInteractionCoordinator` 在有效地形长按开始时调用开始接口，在所有清理路径调用结束接口；重复结束不会产生负倍率或残留状态。
- [ ] 长按范围内移动仍保留长按；走出范围立即取消并恢复全速。
- [ ] 新增回归测试覆盖基础速度、20% 速度、开始/结束恢复和协调器清理调用；相关既有测试通过。
- [ ] 真实运行验证能观察到长按开始后有效速度从 500 变为 100，取消后恢复 500。
- [ ] 相关模块文档同步更新，且不改动建筑、地图、自动拾取与 UI 的既有行为。

## Notes

- 需求中的“物品交互”按本项目现有可辨认的世界物品交互解释为地形卡长按采集/破坏；掉落拾取是 0 行动值的即时自动流程，没有可持续的交互态，不纳入减速。
- “降低 80%”按乘法计算，即保留 20%；不是固定扣除 80 世界像素/秒。
