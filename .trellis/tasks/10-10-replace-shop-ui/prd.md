# 替换商店界面并接入现有功能

## 目标与用户确认

使用用户准备的 ShopNew 场景替换旧商店入口，接入购买、拖拽出售、仓库整理、升级与金币刷新，保留原有交易规则与用户布局素材。

- 用户原话：“那些未提交的东西都是我给你准备的”。全部初始未提交文件均为任务输入，必须保留。
- 用户原话：“那就快干活”。
- 用户批准：“可以，按这个目标创建任务”。
- 用户补充：“我改了点东西，现在可以在spinbox节点里选择出售或购买数量。”
- 用户补充：“当玩家选择点击icon以出售时，如果数量为0，则会提示notice会提示玩家选择数量。”
- 用户补充：“现在即使是更换icon也不会出售了”。
- 用户补充：“点击物品后要显示详情框，如图所示，就像WarehouseNew里的东西一样”。
- 用户补充：“sellarea的icon用右键点击后应该可以清空，且buyarea的itemicon也是，并且不应该随着点击左侧仓库物品而清零”。

## 已核实背景

- `scenes/Shop/ShopNew.tscn` 无功能脚本。仓库网格、整理/升级按钮、买卖详情、返回和金币节点已存在；商品滚动区域缺少网格。
- 用户最新场景已增加 `Shop/BuyArea/Buy/BuyButton`、`Shop/BuyArea/BuyCount/SpinBox`、`Shop/SellArea/SpinBox`；待售图标为 `Shop/SellArea/ItemIcon`，提示为 `Shop/SellArea/ScrollContainer/Notice`。
- 两处 SpinBox 使用用户的 `scripts/export_spinbox_bg.gd` 和自定义主题，场景未覆盖数量范围，Godot 默认最小值 0、最大值 100、步长 1、初始值 0；接入时保留样式与范围。
- `core/autoloads/SceneManager.gd` 的 shop 仍指向旧 `scenes/Shop/Shop.tscn`。
- 旧 `scripts/shop/shop_control.gd` 选中后用按钮交易，每次买或卖 1 件；两侧分页。
- 交易复用 `core/shop/shop_trade_bridge.gd` 与 `core/shop/shop_service.gd`，库存由 GlobalWarehouse、金币由 PlayerWallet、仓库升级由 PlayerProgression 管理。
- WarehouseNew 已有功能；本轮新增背景。item_slot2 新增隐藏 PriceLabel，仓库仍应隐藏价格。
- Godot 编辑器 MCP 已连接 CUSGA，版本 4.7.1-stable。

## 功能要求

1. shop 导航进入 ShopNew，返回按钮回到仓库；旧商店资源保留兼容。
2. 仓库展示全部容量，商品显示全部既有目录，使用滚动区域并复用格子。
3. 点击商品只更新购买区图标、名称、单价和描述。玩家用购买 SpinBox 选择数量，点击现有 BuyButton 才按该数量购买，购买经原有规则执行；数量为 0 时提示选择数量且无副作用。
4. 仓库物品拖入出售区只更新待售图标与卖价，不移除物品、不增加金币。更换图标和修改出售 SpinBox 同样不触发交易。仅点击出售区 ItemIcon 时提交 SpinBox 指定数量；数量为 0 时 Notice 显示“请选择数量”。非法来源、过期快照、空物品、不可售物品或数量不足不得交易，并显示清楚提示。
5. 待售物品保持来源槽位身份；出售不得意外扣除其它槽位里的同类独立物品。数量不足时整笔失败，不自动减少为可售数量；金币增加量为已有卖出单价乘以指定数量。
6. 整理、仓库升级和金币显示使用原有组件，费用准确，满级或余额不足禁用升级。
7. 缓存重入重新订阅和刷新，离开清除选中、待售内容和外部信号，不重复创建格子。
8. 保留用户布局、背景、按钮、SpinBox 主题和格子样式，仅补充功能必需的控件。
9. 同步相关模块文档、《游戏机制与玩法内容》和相关规范。
10. 点击商品和仓库物品显示 WarehouseNew 同款详情框；右键买卖两侧图标清空对应区域。点击左侧仓库物品保留购买区当前商品与数量。

## 验收标准

- 新商店可以导航和直接运行打开，商品、仓库与金币准确显示。
- 买卖成功时金币和物品准确变化；余额或容量不足、非法拖动均无副作用。
- 两处数量为 0 时提交均提示选择数量；出售使用现有 Notice，不扣物品和金币。
- 拖入、更换待售图标、点击商品及改变数量均不交易；只有购买按钮和待售图标的明确点击提交相应数量。
- 出售两件、剩余数量不足、待售来源被整理/替换以及两个同类独立物品位于不同槽位的情况均覆盖验证。
- 整理、升级及返回正确，缓存重入格子复用，金币刷新无重复回调。
- 通过 Godot 编辑器 MCP 针对性测试、新商店/仓库及主场景冒烟、日志检查和真实输入截图；最后只停止游戏。
- 保留所有用户输入改动，提交或推送须另按本地规则取得批准。

## 范围外

不调整商品目录、价格、初始金币、升级费用、容量公式或存档格式；不涉及局内商店、战斗、地图及新依赖。
