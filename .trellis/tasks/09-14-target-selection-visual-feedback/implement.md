# 目标选择视觉反馈实施计划

## 实施步骤

1. 在 `entities/Monster.cs` 扩展现有卡面视觉接口：缓存描边和原始颜色，提供安全的静态状态、呼吸启停、变暗与描边操作；所有新增公开方法附中文 XML 文档。
2. 在 `scenes/monster_scenes/monster.tscn` 添加默认隐藏的 `TargetSelectionOutline`，使其覆盖怪物卡面并随现有视觉缩放同步。
3. 在 `scripts/card_scripts/card_manager.gd` 新增 Inspector 可调的目标选择视觉参数与局部状态缓存；将现有目标范围推导为正常、可选、悬停、主选中、次级选中、不可选状态，并在点击、拖拽、取消和失去回合时统一刷新或还原。
4. 保留既有时间轴高亮和结算目标解析；将旧的单一 `set_entity_highlight` 调整为兼容入口或由状态应用层调用，避免其他输入路径残留视觉状态。
5. 新增 `tests/godot/target_selection_visual_tests.gd`，覆盖怪物卡的描边、变暗、呼吸停止和复位接口；更新 `docs/游戏机制与玩法内容.md`，记录状态规则及全部默认数值。
6. 在 `临时反馈文档.md` 追加本次学习反馈摘要与分点 Git 提交描述。

## 验证计划

- 运行 `env CI=true dotnet build CUSGA.sln --no-restore`，检查 C# 怪物视觉接口编译通过。
- 本机按项目本地规则不运行 Godot Mono；通过 C# 编译、静态差异审查与新增聚焦 Godot 测试脚本交付验证入口，待具备 Godot 运行环境时执行该脚本与战斗场景烟雾启动。
- 手动验证点击与拖拽两种模式下的单体、扩散、自身、随机敌人与全体敌人卡：确认状态切换不影响确认、取消、能量与结算。
- 检查工作区差异仅包含预期的视觉逻辑、怪物场景、测试、机制文档、任务工件和临时反馈。

## 审查要点

- 主选中倍率必须大于次级倍率，且两者均停止呼吸并显示绿色边框。
- 自身目标卡只能使敌人变暗，不得添加玩家 HUD 标记。
- 随机敌人与全体敌人的所有受影响敌人必须直接显示绿色边框。
- 目标选择结束、切换模式、敌方回合或目标失效时，所有怪物必须恢复正常色彩、无边框且无残留 Tween。
- `BattleManager` 的行动缩放、既有时间轴高亮与卡牌结算语义必须保持不变。
