# 九宫格房间内容与地形卡生命周期

日期：2026-09-25。状态：实施已获用户确认。

## 目标

玩家周围有效的 3×3 房间不仅保留地图场景，还要让其中的地形卡、掉落物和已有建筑同时存在并正常运行。窗口外释放运行节点，但房间内容状态继续保留；返回时按原坐标和原状态重建。地形卡使用 `Item` 场景，掉落物使用独立的 `Loot` 场景。测试期默认只在本次运行保留局内状态，同时准备可切换的跨重启局内存档模式。

## 已确认的背景

- `UIMapWorldView` 已按 `MapWorldModel.get_window_positions()` 保留最多九个有效完整房间，并释放窗口外房间节点；房间尺寸为 `1280×720` 世界像素。[依据：`scripts/map_scripts/UIMapWorldView.gd:155`、`core/map/map_world_model.gd:166`]
- `UIRoomBoardPresenter` 目前每次进入房间都会清空全部卡牌，只重建当前房间；`RoomTerrainStore` 则已经按房间保存地形实例。[依据：`core/map/UIRoomBoardPresenter.gd:88`、`core/map/room_terrain_store.gd:16`]
- 掉落卡目前只存于 `BoardController` 的活动视图数组；建筑有 `RoomBuildingStore`，但表现层只重建当前房间。[依据：`core/board/board_controller.gd:57`、`core/building/room_building_store.gd:3`、`core/building/building_controller.gd:466`]
- `scenes/ItemTerrian/Item.tscn` 以 `CharacterBody2D` 为根，`scenes/Loot/Loot.tscn` 以 `Area2D` 为根；地形的 `Collision` 是物理碰撞形状，两个视图的 `Interaction/CollisionShape2D` 是鼠标点击命中形状；两个场景都由 `AnimationPlayer` 提供 `Idle` 与 `Hover`。[依据：两个场景当前文件]
- 成功拾取当前先把物品放进背包，再向 HUD 背包按钮飞行；目标需要改为 `PlayerChar`。[依据：`core/gameflow/world_interaction_coordinator.gd:348`]
- `SaveManager` 已支持 `global` / `run` 参与者协议，但当前 `save_now()` 会把两种作用域一同写进主存档；因此不能仅把新状态注册为 `run` 就声称默认是“仅本次运行”。[依据：`core/save/save_manager.gd:364`、`:456`]
- 存档规范要求 `SaveManager` 是第一个 autoload，但当前 `project.godot:44` 将其列在其他存档参与者之后；跨重启模式实施时必须修正并验证真实启动顺序。该差异是现有配置问题，规划阶段不改动。[依据：`project.godot:31`、`core/save/save_manager.gd:252`]

## 需求

| 编号 | 要求 |
|---|---|
| R1 | 当前房间周围 3×3 范围内，所有实际存在的房间都要同时实例化其完整场景和本任务涉及的房间内容：地形卡、未拾取掉落物、已有建筑。该范围外不得保留这些内容的运行节点。 |
| R2 | 首次生成的地形配置、房间内局部坐标、采集/占用/成长/冷却状态和掉落物的物品、数量、最终落点必须由与视图节点分离的房间状态保存。离开、释放、返回或再次进入不能重新抽取已经生成的内容，也不能复活已拾取的掉落物。 |
| R3 | 地形卡使用 `Item` 场景，掉落物使用独立 `Loot` 场景。地形卡的 `Collision` 专门处理玩家与实体的物理碰撞；两个场景的 `Interaction` 专门处理鼠标命中。掉落物不阻挡玩家，但仍能被鼠标点击；地形卡的实体碰撞按配置启用。视觉动画不得移动碰撞或交互形状。 |
| R4 | 拾取成功后，掉落物的视觉飞向移动中的 `PlayerChar`，而不是 HUD 背包；同一掉落只能结算一次。背包拒收时掉落仍留在原位且可再次点击。 |
| R5 | `Item` 与 `Loot` 都有可调的 `Idle` 与 `Hover` 两段果汁感动画。`Idle` 不含任何 `position`、`rotation` 关键帧；两段动画只改变视觉子树，不改变房间状态坐标及命中区域。 |
| R6 | 地形生成、碰撞、交互、散射、动画和保存策略提供有中文说明的 `Resource` / `@export` 配置，能在 Godot 检查器中调试；公共 GDScript 类与方法遵循项目的中文 `##` 文档注释规则。 |
| R7 | 局内状态默认采用仅本次运行的模式，退出游戏后不会从磁盘恢复本局。另一个跨重启模式必须能在启动前配置，也能在本局运行时切换；切换不重置当前房间内容。局外存档继续独立自动保存。 |
| R8 | 跨重启模式恢复随机地图布局与连接、当前房间和玩家世界坐标，以及本任务所依赖的地形、掉落、建筑、游戏时间和玩家局内库存状态；恢复顺序不能让开局带入流程覆盖读档结果。 |
| R9 | 已有的地形长按/重复采集、掉落散射、建筑放置与拆除、战斗时世界隐藏和连续跨房移动继续可用。3×3 内的邻房内容必须真实运行，不能只在玩家进入时才临时补生。 |
| R10 | 跨重启模式下若在战斗中退出，下次继续本局恢复到进入该场战斗之前的世界快照，不恢复战斗中的行动队列、动画或临时目标。 |

## 验收标准

- [ ] AC1（R1）：在有斜对角房间的地图上，读取活动坐标与场景树，地形、掉落、建筑的运行节点只存在于有效 3×3 内；移动一格后新增房间内容先就绪，再释放窗口外内容。
- [ ] AC2（R2）：记录地形局部坐标、类型和采集/冷却状态，离开到窗口外再返回完全一致；掉落的数量和最终落点也一致，已拾取物不会重现。
- [ ] AC3（R3）：玩家被配置为阻挡的地形实体挡住，能够穿过掉落物；鼠标仍能点击掉落；视觉缩放时两个命中形状的位置与尺寸不跟着变化。
- [ ] AC4（R4）：成功拾取只向库存增加一次，掉落立即失去鼠标命中和物理碰撞，视觉追随 `PlayerChar` 完成飞入；库存满时不移除、不飞走。
- [ ] AC5（R5）：查看 `Item` 动画轨道，`Idle` 不含 `position` / `rotation`；持续播放、悬停、离开和窗口卸载不会出现跳位或遗留动画节点。
- [ ] AC6（R6）：调整对应 `.tres` 或导出字段后，地形密度、碰撞开关、掉落散射与动画参数按配置生效，且默认值与实际资源路径可追溯。
- [ ] AC7（R7-R8）：默认模式退出再进入是新局且原局外存档仍在；切换至跨重启模式后退出、重启可恢复同一地图、玩家位置和所有列明的局内状态；运行时往返切换不丢失当前内存状态。
- [ ] AC8（R9）：现有地形采集、掉落、建筑和战斗返回流程通过回归测试；主场景无脚本解析、资源加载或本次改动引入的运行时错误。
- [ ] AC9（R10）：战斗中退出并重启后，地图、玩家、房间内容和背包与进入战斗前快照一致；不会加载半场战斗状态。

## 范围边界

- 不改变 `MapPositionCreate` 的随机地图生成规则、地图方向连接判定、房间 TileMap 布局或玩家连续移动规则。
- 不增加玩家可见的存档按钮、掉落自动吸取或新的地形/建筑玩法。
- 完整房间 TileMap 仍是一个场景实例，不逐瓦片创建 `Item`。
- 本任务的“所有房间内容”指当前已有且与房间坐标关联的地形卡、掉落物、建筑及其交互；全局 HUD、玩家本体和战斗场景不复制为九份。

## 已确认的战斗存档边界

- 用户确认跨重启模式只保留进入战斗前的世界快照。战斗中途的具体进度不属于本任务的保存范围。
