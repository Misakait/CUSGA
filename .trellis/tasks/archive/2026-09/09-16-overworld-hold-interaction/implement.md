# 局外长按交互系统实施计划

## 实施步骤

1. 新增共享行动值到长按秒数的换算常量与纯函数；让可重复采集继续使用该统一比例。
2. 新增目标右下角圆环 HUD 表现组件和单一活动长按控制器；在主场景中装配这两个节点。
3. 迁移棋盘正行动值地形交互：按下开始、松开或全局释放取消、完成才执行；保留零行动值拾取单击。
4. 迁移地图方向按钮：将 `pressed` 改为 `button_down` 开始与 `button_up` 取消，完成后调用原有移动流程。
5. 删除卡牌上的旧线性长按条和对应陈旧测试，改为验证全局圆环组件及输入契约。
6. 同步《游戏机制与玩法内容》、任务文档与临时反馈文档。

## 验证

- 更新或新增最小 Godot 测试脚本，覆盖圆环的默认隐藏、进度显示与取消复位，以及正/零行动值的时长规则。
- 使用 `env CI=true dotnet build CUSGA.sln --no-restore` 验证 C# 编译；本机项目约定不运行 `godot-mono`。
- 检查场景信号是否全部由 `pressed` 迁移到成对的 `button_down`/`button_up`，并确认没有遗留卡牌线性进度引用。
- 在提交前检查改动范围与任务预期一致。

## 风险与检查点

- 地图移动涉及异步驻守战斗与淡出：完成回调需在开始原有协程后锁定重复移动。
- 可重复采集的实际耗时受装备影响：必须在开始长按时快照，完成时用同一数值结算。
- HUD 圆环必须忽略鼠标输入，不能拦截地图按钮或棋盘卡牌。
