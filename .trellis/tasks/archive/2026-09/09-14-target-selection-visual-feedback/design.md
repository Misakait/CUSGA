# 目标选择视觉反馈设计

## 边界与职责

| 位置 | 职责 | 不负责 |
|---|---|---|
| `scripts/card_scripts/card_manager.gd` | 从既有目标类型、当前输入模式、鼠标悬停与点击选择推导每个怪物卡的视觉状态；统一触发状态切换与清理。 | 改变目标合法性、随机结果、能量或行动结算。 |
| `entities/Monster.cs` | 复用现有“不缩放血条”的卡面变换缓存，执行静态缩放、循环呼吸、卡面变暗与边框显示。 | 保存卡牌选择状态或决定哪些怪物是合法目标。 |
| `scenes/monster_scenes/monster.tscn` | 提供隐藏的 `TargetSelectionOutline` 绿色描边节点。 | 编写选择逻辑。 |
| `tests/godot/target_selection_visual_tests.gd` | 验证怪物卡面接口可切换描边、变暗和呼吸状态。 | 覆盖战斗结算规则。 |

## 状态模型

`CardManager` 为当前场上的每个有效怪物卡推导唯一状态，并只在状态实际变化时调用怪物视觉接口，避免 `_process` 每帧重建 Tween。

| 状态 | 缩放 | 呼吸 | 边框 | 颜色 |
|---|---:|---|---|---|
| 正常 | `1.50` | 无 | 隐藏 | 原色 |
| 可选 | `1.53 ↔ 1.56` | 循环，单程 `0.50s` | 隐藏 | 原色 |
| 悬停 | `1.60` | 停止 | 隐藏 | 原色 |
| 主选中 | `1.66` | 停止 | 绿色，宽 `3px` | 原色 |
| 次级选中 | `1.60` | 停止 | 绿色，宽 `3px` | 原色 |
| 不可选 | `1.50` | 停止 | 隐藏 | 灰暗倍率 `0.45` |

这些数值会作为 `CardManager` 的导出参数，便于在 Inspector 中调整；绿色边框默认色为 `Color(0.25, 1.00, 0.35, 1.00)`。怪物当前的 `monster_normal_scale` 与 `monster_hover_scale` 保持名称和现有含义，分别作为正常与悬停缩放的默认值。

## 目标类型到视觉状态

| 目标类型 | 敌人卡状态 |
|---|---|
| 自身 | 全部不可选/变暗；不新增玩家 HUD 标记。 |
| 单体敌人、任意单体 | 所有在场敌人可选；点击模式在未点击前仅将鼠标下目标设为悬停，点击后设为主选中；拖拽模式悬停目标即预览主选中。 |
| 扩散敌人 | 所有在场敌人可选；主目标为主选中，左右相邻目标为次级选中。 |
| 全体敌人、随机敌人、全体单位 | 所有受影响的在场敌人自动主选中，直接显示绿色边框。 |

不属于上述受影响集合的怪物一律不可选并变暗。玩家仍可作为既有结算中的默认自身目标，但不新增任何玩家 UI 表现。

## 数据流与兼容性

1. 选择点击模式卡牌、开始拖拽、拖拽位置变化、点击目标、切换操作模式、取消选择或失去玩家回合时，`CardManager` 重新推导怪物视觉状态。
2. 点击模式优先使用已点击的 `_selected_click_target`；未选中时读取鼠标下的卡槽作为悬停预览。拖拽模式使用拖拽卡当前命中的卡槽作为主目标预览。
3. `CardManager` 保留既有 `_resolve_intended_targets` 的目标范围与时间轴高亮语义；视觉状态只消费其同一套目标类型、场上怪物顺序与主目标信息。
4. `Monster` 在开始新的目标状态前终止自己的目标选择呼吸 Tween，并复用既有视觉节点缓存同步卡面、名称、属性与状态栏的缩放位置；`HealthBar` 不参与缩放或变暗。
5. 边框是怪物场景中默认隐藏的 `Line2D`，随卡面缩放而变化；缺少该节点时 C# 接口只降级跳过边框，不阻断战斗。
6. 出牌确认前会走既有清理出口，因此行动结算与敌方回合的 `TweenVisualScale` 不会与目标选择呼吸动画并存。

## 风险与回滚

- `Monster.TweenVisualScale` 当前仅由 `CardManager` 和 `BattleManager` 调用。新增目标选择动画必须在每次状态切换时终止旧 Tween，避免多个 Tween 同时写入相同卡面属性。
- 新视觉状态只能读取既有 `SkillTargetingType`，不得改写 `_selected_click_target`、`Action`、`DeckManager` 或 `BattleManager` 的结算输入。
- 回滚路径为删除 `CardManager` 的状态推导调用、移除 `Monster` 的目标选择视觉接口及场景描边节点；不会涉及卡牌资源或存档迁移。
