# Battle 打击感与果汁感实施计划

## 实施前提

- 仅在用户审阅并明确批准 `prd.md`、`design.md` 与本计划后执行。
- 实施采用单一主任务内的顺序步骤：后续表现层依赖先完成的结算结果契约，不能跳过第一阶段直接在 `BattleManager` 堆叠特效。
- 不改变伤害、目标、状态、能量、卡牌弃置或回合规则；任何发现的规则变化必须退回规划阶段确认。

## Phase A：结算结果契约（最高优先级）

1. 新建只读 `DamageResolutionResult`、`DamageResolutionTrace` 与必要枚举，明确暴击、闪避、实际伤害、护盾吸收、护盾破裂、封顶和致死的语义。
2. 将 `DamageReceiverComponent.ReceiveDamage` 改为构建、返回并发射每段独立的结算结果；保留现有 `DamageTaken`、`ValueChanged` 和伤害数值行为。
3. 让 `DamageEffect` 为 payload 写入段号、总段数和目标角色的表现元数据；不让其引用任何 UI、动画节点。
4. 让 `ShieldStatusInstance` 与 `BossDamageCapStatusInstance` 只向 trace 记录自身造成的吸收/封顶，不改变原有 Hook 优先级和伤害修改方式。
5. 为闪避、普通伤害、暴击、护盾完全吸收、护盾破裂、过量伤害与多段段号编写聚焦测试。

**检查点：** 结果对象的字段与实际扣血、状态 Hook 结论一致；没有表现系统时，旧玩法表现和数值保持兼容。

## Phase B：表现基础设施与场景锚点

1. 新建 `CombatFeedbackProfile` Resource，参数化配方、多段浮字时长与错开延迟，以及完整/减弱预设。
2. 新建 `CombatFeedbackDirector`、浮字对象池、屏幕脉冲与 Hit Stop 控制器；所有新增公共类型写中文 XML 文档或 GDScript 文档注释。
3. 在 battle 场景添加导演层、CanvasLayer 和 `PlayerFeedbackAnchor`；在怪物场景添加可复用的卡面中心锚点。锚点只负责坐标转换，不包含玩法规则。
4. 让导演层连接玩家与当前/新生成怪物的 `DamageResolved`，并在场景退出时断开、回收对象、还原 `Engine.TimeScale` 和根节点位置。
5. 在浮字锚点或屏幕脉冲节点缺失时验证安全降级：其余结算与表现仍可运行，不阻塞行动队列。

**检查点：** 双方任意一段标准伤害都会产生一个统一事件，且导演层故障不会中断结算。

## Phase C：核心命中配方与动作链路

1. 保留卡牌飞行，加入可配置的切入缩放/残影；移除卡牌飞行后预先触发的怪物 `play_enemy_hit_feedback`。
2. 实现普通命中、暴击、闪避、护盾吸收/破裂和治疗的结果配方；状态变化不创建浮字。
3. 让目标反应通过统一接口分别适配怪物卡面与玩家 HUD/角色区域，禁止将 `UI/HpBar` 路径写入伤害公式或状态类。
4. 将 `ATTACK` 临时分支统一接入 `DamageReceiverComponent`；审查所有其他直接调用 `HealthComponent.TakeDamage` 的战斗来源，确保不会绕过反馈结果。
5. 实现多段和范围调度：每段独立浮字、过程紧凑字号、多段时长加速、按段号错开；不设置单目标或全局浮字上限，主次目标仍保持错峰与高优先级受力控制。

**检查点：** 单体、随机、全体、扩散、敌方技能和多段伤害都从真实结算结果产生反馈；普通命中不因范围/段数造成震屏堆叠。

## Phase D：击杀、Hit Stop 与强度设置

1. 拆分怪物的逻辑死亡和视觉死亡：立即退出 `active_monsters`/目标池，视觉节点在导演层播放一次性收尾后释放；处理补位与退出场景的竞态。
2. 对玩家致死增加 HUD/角色区域反馈，但保留当前战斗结束和实体存活规则。
3. 实现唯一 `CombatScreenImpulse`，只允许高优先级结果申请 Hit Stop；添加冷却、恢复 token、退出还原与减弱模式禁用规则。
4. 扩展 `BattleSettingsPanel` 和持久化设置，使 `full` / `reduced` 可立即生效并跨重启保留。
5. 完成默认 profile 的参数微调：优先检查连续多段、范围、击杀补位和玩家被敌人连续攻击四种压力场景。

**检查点：** 不会永久慢放、根节点不会漂移、死亡目标不会再次受击；`reduced` 模式保留数字与关键结果，但没有高强度震动/闪白/Hit Stop。

## Phase E：表现参数、文档与回归

1. 更新 `CombatFeedbackProfile` 的颜色、敌方下冲、浮字和结果标签参数。
2. 更新 `docs/游戏机制与玩法内容.md`：新增表现规则、完整/减弱设置、Hit Stop 范围、视觉预算和不改变玩法数值的边界。
3. 在项目的临时反馈与提交规范要求下，补充学习反馈摘要和分项提交描述。
4. 运行 C# 构建与新增/既有的相关测试；GDScript 和场景改动按当前本地环境约束进行静态审查，不使用 Godot Mono。

**检查点：** 资源许可可追溯，文档成为反馈规则的权威快照，测试覆盖关键结果数据和节流边界。

## 建议验证矩阵

| 场景 | 必须观察到 | 禁止发生 |
| --- | --- | --- |
| 玩家单体普通命中怪物 | 真实伤害数字、轻受力、一次短命中音 | 结算前闪白、重复数字 |
| 敌人技能命中玩家 | 玩家锚点受击、数字、HUD 正确更新 | 只更新血条无反馈 |
| 闪避 | `MISS`/闪避与残影 | 伤害数字、血量扣除、重击音 |
| 暴击 | 深红放大数字、重击、短 Hit Stop | 多次叠加慢放、普通级反馈 |
| 护盾完整吸收/破裂 | 灰色吸收数字/破裂反馈与正确数值 | 将封顶或减伤误报为护盾 |
| 5 段伤害 | 5 条独立数字按段号快速错开、节奏连续 | 同帧刷 5 次震屏或数字完全重叠 |
| 全体/扩散 | 主次错峰、一次共享冲击 | 每个目标都震屏/Hit Stop |
| 击杀与补位 | 目标立刻不可选、视觉收尾完成、新怪正常进入 | 已死目标再次受击、节点泄漏 |
| 完整/减弱切换 | 数字和关键信息均保留 | 减弱模式仍强震屏或永久改变设置 |

## 构建与测试

实施时在确认目标存在后使用：

```powershell
env CI=true dotnet build CUSGA.sln --no-restore
env CI=true dotnet test tests/CUSGA.Tests/CUSGA.Tests.csproj --no-restore
```

如果测试项目或解决方案结构在实施前发生变化，先重新调查实际目标再执行；当前本地环境不运行 Godot Mono。

## 高风险文件与回滚点

| 风险文件/区域 | 风险 | 回滚点 |
| --- | --- | --- |
| `DamageReceiverComponent.cs`、状态 Hook | 影响全部伤害 | Phase A 独立提交；保留旧信号与公式路径 |
| `DamageEffect.cs` | 多段元数据或目标顺序错误 | 不改循环/伤害调用顺序，只附加元数据 |
| `Monster.cs`、`monster_manager.gd` | 死亡延迟导致补位或清理问题 | Phase D 独立提交；导演不存在时立即销毁 |
| `battle_manager.gd`、`deck_manager.gd` | 行动队列被动画阻塞 | 仅删除预结算命中调用，结果动画不 await 权威结算 |
| `battle.tscn`、`monster.tscn`、玩家 UI | 节点路径或锚点缺失 | 可选节点查询和无锚点安全跳过 |
