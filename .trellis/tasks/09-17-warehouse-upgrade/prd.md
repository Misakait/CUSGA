# 仓库改造与容量升级系统

## Goal

把局外仓库从「拖拽卡牌」改成与商店一致的「点选 + 按钮」交互并重排布局；让**带入游戏的栏位数量**与**仓库容量**都变成可用金币升级的动态值；同时把商店的上架方式改成「把物品 `.tres` 拖进 inspector 即上架」。

## Background

- 旧局外仓库由 `scenes/Warehouse/Warehouse.tscn` + `scripts/warehouse/*.gd` 组成，交互全部依赖拖拽：`inventory_grid.gd` 用射线拾取卡牌、`snapper.gd` 负责吸附、`inventory_card_slot.gd` 处理槽位互换。
- 旧实现让界面持有库存的**副本**，靠 `warehouse_control.init()` 拷入、`exit()` 拷回与 `GlobalWarehouse` 同步。任何一条路径漏写回就会丢改动。
- 带入栏固定 5 个（`usercard_1..5`），仓库容量固定 27（`InventoryComponent.Capacity` 默认值）。
- `map_control.gd` 在 `_ready()` 里把 `ItemsControl.warehouse_to_player` 一次性灌进局内背包并清空，**对数量无感知**，因此带入栏数量可以自由变化。
- 商店原本的上架规则是「`ItemData.BuyPrice > 0` 即自动上架」，要加新商品必须逐个去改物品资源的买价。
- 局外界面（商店）已完成，素材与配色已定型：`背包格子-未选中-选中的样子.png`、`按钮-未选中-选中-按下的样子.png`（3 列颜色 × 3 行状态，每格 64×32）。

## Requirements

### R1. 仓库交互改为点选 + 按钮

- 移除拖拽：不再有卡牌射线拾取、吸附、槽位互换。
- 点选仓库格子 → 点「放入」→ 该堆叠整堆进入带入栏。
- 点选带入栏格子 → 点「取出」→ 退回仓库。
- 保留「整理背包」（按名称排序）与「返回主菜单」。
- 保留「进入商店」入口，且商店应能看到仓库的最新内容。

### R2. 仓库 UI 重排（对齐商店）

- 与商店共用格子素材、三色按钮素材与暗色面板配色。
- 每个仓库格子显示：图标 + 物品名称 + 数量。
- 仓库分页；带入栏按当前解锁数量渲染。
- 布局对称、留白合理，标题/容量/金币信息一目了然。

### R3. 带入栏数量可升级

- 初始 5 个，每级 +1，最多 10 个（5 次升级）。
- 升级费用：200 / 350 / 550 / 800 / 1100。
- 未解锁的栏位必须**视觉上明显区别于可用空位**，否则玩家看不出升级买到了什么。
- 等级跨场景、跨重启保留。

### R4. 仓库容量可升级

- 初始 27 格，每级 +9（正好一行），最多 54 格（3 次升级）。
- 升级费用：300 / 600 / 1000。
- 升级后仓库必须真的能放下更多物品（`InventoryComponent` 实际扩容），而不只是界面多画几个格子。
- 等级跨场景、跨重启保留。

### R5. 升级的失败语义

- 金币不足时升级必须**零副作用**：等级、容量、余额都不变。
- 已满级时再次升级返回失败，且不扣钱。
- 存档里的非法等级（负数、超上限）必须被收窄到合法范围，而不是算出负容量。
- 升级按钮在余额不足或已满级时应直接禁用并说明原因，而不是让玩家点了才知道。

### R6. 商店上架改为「拖入即上架」

- 新增商品目录资源，把物品 `.tres` 拖进其数组即上架。
- 未自行配置买价的物品被拖入后必须仍可交易：使用目录的兜底买价。
- 兜底价**只对目录里显式列出的物品生效**，不能把所有零价物品都变成商品。
- 目录为空时保持引入前的行为（所有已定价物品上架），确保既有 88 件商品不受影响。
- 显式拖入的顺序即货架顺序。

### R7. 验证

- 用 Godot 4.7.1 headless 冒烟全部既有场景，确保删脚本 / 改场景没有回归。
- 升级与买卖的规则分支要有自动化覆盖。
- 关键交互用真实鼠标事件在运行中的游戏里验证，并截图确认视觉。

- [x] AC2：点选仓库物品后点「放入」，该物品整堆进入带入栏，仓库中对应数量减少。
- [x] AC3：点选带入栏物品后点「取出」，整堆退回仓库，带入栏对应栏位清空。
- [x] AC4：「整理背包」仍能按名称排序仓库内容。
- [x] AC5：仓库格子显示图标 + 名称 + 数量；布局与商店风格一致。
- [x] AC6：带入栏初始 5 个可用、5 个未解锁；未解锁栏位明显变暗。
- [x] AC7：点「带入栏 +1」后可用栏位 +1、金币按当前费用减少、按钮费用刷新为下一级。
- [x] AC8：点「仓库扩容」后 `GlobalWarehouse.Capacity` 实际增加 9、金币按当前费用减少、总页数随容量变化。
- [x] AC9：金币不足时升级失败，等级 / 容量 / 余额全部不变。
- [x] AC10：满级后容量 54、带入栏 10、下一级费用显示为 0、再点升级失败且不扣钱。
- [x] AC11：升级等级写入 `user://settings.cfg` 的 `player/warehouse_level` 与 `player/carry_level`，重启后保持。
- [x] AC12：存档里把等级改成负数或超上限时被收窄到合法范围。
- [x] AC13：把 `BuyPrice = 0` 的物品拖进商品目录后，它出现在商店且可按兜底价成交。
- [x] AC14：把物品从目录移除后它不再出现；关闭自动上架后商店只卖显式列出的商品。
- [x] AC15：未挂目录时商店仍上架全部已定价物品（88 件），行为与改动前一致。
- [x] AC16：Godot 4.7.1 headless 冒烟 `Warehouse` / `Shop` / `Main` / `main_menu` 四个场景均无 `SCRIPT ERROR`。
- [x] AC17：删除 4 个旧仓库脚本后全部场景与规则测试仍通过。

## Constraints

- 不改 `ItemsControl.warehouse_to_player` / `player_to_warehouse` 这两个契约，`map_control.gd` 不做任何改动。
- 带入栏与仓库容量**只增不减**，不实现降级。
- 升级数值集中在 C# 规则层一处，界面不得自行硬编码费用。
- 公共 C# API 写中文 XML 文档；注释解释**为什么**。
- 局内战斗与合成流程不受影响。

## Out Of Scope

- 带入栏/仓库的**降级**、退款、重置。
- 带入栏在局内的使用方式变更（仍由 `map_control.gd` 一次性灌入背包）。
- 更多的升级项（背包扩容、移速、掉率等）。
- 商店的多商人 / 分店体系。
- 为旧拖拽系统保留兼容层。
