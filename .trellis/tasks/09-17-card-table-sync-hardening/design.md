# 卡牌表格安全同步设计

## 架构

Godot 插件是面向编辑器的薄交互层，只负责菜单、确认对话、解释器选择、启动脚本、展示结果以及在成功时重新扫描资源。Python 脚本继续作为唯一的数据同步层，负责读取、校验、备份、导入/导出和退出码。

## 用户流

1. 用户首次选择“打开卡牌表格”时，插件在编辑器中显示一次操作顺序；用户确认后，若工作簿不存在，插件安全导出一次；然后在系统默认表格程序中打开 XLSX。
2. 用户保存并关闭工作簿。
3. 用户选择“安全同步卡牌表格”，确认后运行 Python 的自动同步模式。
4. 脚本先完整校验将要导入的表格；失败时不写资源并以非零退出。
5. 成功时，脚本先备份受影响 `.tres`，再原子写入资源和表格。插件只在此时扫描资源目录并展示结果。

首次引导状态只保存在 Godot 编辑器的项目元数据中，不写入表格或资源；同步确认弹窗每次显示，作为覆盖风险的常驻防线。完整字段说明与恢复方式由 `card_table/README.md` 承载。

## 执行契约

Godot 每次调用生成唯一 `request_id`，并把结果文件路径与请求标识传给 Python。Python 将 `success`、`action`、`changed_files`、`warnings`、`error` 和 `request_id` 以 UTF-8 JSON 原子写入结果文件，同时保留单行控制台摘要用于人工排查。

Godot 优先读取结果文件，并明确以 UTF-8 解码；只有请求标识匹配、退出码为零且 `success=true` 时显示成功。结果文件缺失、JSON 损坏、请求标识不匹配、非零退出或 `success=false` 都视为失败。控制台摘要仅作为结果文件不可读时的兼容回退，且同样必须匹配本次请求标识。

## 数据保护

- 表格的显式资源路径必须使用 `res://`，解析后的绝对路径必须在其所属受管目录内，且扩展名为 `.tres`。
- 所有格式和引用错误在预检阶段汇总，预检失败时不会进入写入阶段。
- 导入写入前复制受影响的已存在 `.tres` 到 `card_table/.sync_backups/<timestamp>/`；备份数量受限，目录被 Git 忽略。
- 写操作统一写入同目录临时文件后使用 replace 提交。XLSX 锁定时仍按既有设计写入 pending 文件，最终摘要如实标明。

## 兼容性与取舍

- 保留 `--export`、`--import`、`--sync` 与 `--auto`，避免破坏 README 中的命令行工作流；编辑器只暴露推荐的自动同步入口。
- 不引入专用 XLSX 库，继续使用标准库，避免给 Godot 编辑器环境添加 Python 依赖。
- 编辑器中的同步仍可同步等待脚本完成，以保持结果文件、弹窗与资源扫描的因果顺序；通过确认、预检、请求标识和清晰进度降低误操作与状态串线风险。

## 回滚

同步失败时，原子写入保证原文件可用；同步成功但业务数据不符合预期时，可从本次备份目录还原受影响资源，或使用 Git 回退已追踪资源变更。
