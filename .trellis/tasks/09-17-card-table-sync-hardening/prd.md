# 加固卡牌表格同步

## Goal

让非程序使用者能够以“打开表格 → 保存并关闭 → 安全同步”的最少步骤维护卡牌数据；任何输入、写入或执行失败都必须显式失败，且不能留下半写入的数据或误导性成功提示。

## Background

- `addons/card_csv_sync/card_csv_sync_plugin.gd` 目前提供三个独立的 CSV 菜单动作，使用 `OS.execute("python", ...)` 同步执行脚本。
- `card_table/export_current_cards.py` 管理 66 条技能和 53 条怪物数据，并直接写入 CSV、XLSX 与 `.tres` 资源。
- 既有审查确认：菜单调用方无法区分脚本成功与失败；CSV/XLSX 写入结果被忽略；用户提供的 `resource_path` 未限制在受管资源目录内；导入缺少完整的表格预检；文本替换没有限定在 `[resource]` 块。

## Requirements

### R1 — 一个推荐同步入口

- 将导出、导入、同步三个低层菜单收敛为一个面向日常工作的“安全同步卡牌表格”入口。
- 另提供“打开卡牌表格”入口：首次使用时生成工作簿，之后仅打开现有工作簿，不覆盖用户编辑内容。
- “打开卡牌表格”首次使用时显示一次完整的傻瓜式操作顺序；同步前每次显示确认提示，明确说明同步方向、双端同时编辑的覆盖风险、XLSX 锁定行为、表格校验和本地备份。
- 成功、无变更、失败三种结果必须在 Godot 编辑器中明确区分；失败不得扫描资源文件系统或显示成功信息。

### R2 — 可判定的执行结果

- Python CLI 必须以退出码表达成功或失败；脚本应把写入失败升级为失败状态。
- GDScript 插件必须以结构化结果处理退出码、输出和变更后的文件集合，而非通过空字符串推断状态。
- Python 必须把最终状态以 UTF-8 原子写入结果文件，并回传 Godot 为本次调用生成的请求标识；Godot 只接受请求标识匹配的结果，避免控制台编码和旧文件污染状态。
- 只有“退出码为零、结果文件属于本次请求且 `success=true`”才可显示成功；摘要缺失、标识不匹配、非零退出或 `success=false` 都必须显示失败。
- Python 解释器需要支持 Windows 常见的 `py -3`，同时保留可配置/可回退的跨平台执行方式。

### R3 — 导入前校验与受控写入

- 在改写任意 `.tres` 前，完整读取并校验表头、必填标识、重复标识、枚举、数值、资源路径及技能/怪物关联；出现一项错误时不改写任何资源。
- 只允许写入三个受管目录的 `.tres` 文件：技能卡、战斗技能与怪物资源目录；拒绝路径穿越、非 `res://` 路径和非 `.tres` 文件。
- 导入前为将改写的资源创建带时间戳的本地备份，保留有限数量，且备份目录不进入版本控制。

### R4 — 原子化与准确的文件输出

- CSV、XLSX、同步状态和 `.tres` 写入必须采用同目录临时文件后原子替换的方式。
- 当 CSV 或 XLSX 被占用、不可写或写入失败时，整个操作以失败结束；只允许保留已有的 XLSX pending 工作簿语义，且日志必须报告真实目标路径。

### R5 — 资源编辑边界与文档

- 现有 `.tres` 属性更新只可匹配其 `[resource]` 段，不能误改子资源同名属性。
- 保持当前的 XLSX/CSV 兼容性、pending XLSX 工作流与手工命令；更新卡牌表格 README，使推荐流程与菜单名一致。

## Acceptance Criteria

- [ ] 仅保留“打开卡牌表格”和“安全同步卡牌表格”两个用户菜单，且同步需要确认。
- [ ] 当 Python 不可执行、校验失败或任何写入失败时，编辑器显示错误，不打印成功文案且不触发资源扫描。
- [ ] 成功、无变更、失败三种结果均通过 UTF-8 结果文件准确传递；旧请求结果不得被本次操作接受。
- [ ] 对缺少必需列、重复路径/标识、非法枚举/数值、无效关联或越界 `resource_path` 的表格，同步返回非零且不改写 `.tres`。
- [ ] 所有成功写入均为原子替换；将要改写的 `.tres` 在写入前生成可恢复备份。
- [ ] 被 Excel/WPS 占用的 XLSX 使用 pending 工作簿时，日志和编辑器反馈显示 pending 的真实路径。
- [ ] 资源根段替换不会匹配或修改子资源的同名属性。
- [ ] Python 静态语法检查、针对新增校验与原子写入的测试、以及适用的 Godot 脚本检查通过。
- [ ] `card_table/README.md` 说明新的傻瓜式流程、确认与备份行为。

## Out of Scope

- 不把所有卡牌复杂 Effects、成长属性或新字段展开到表格。
- 不引入自动文件监控、后台云同步或第三方表格服务。
- 不修改现有卡牌与怪物数值或资源内容。
