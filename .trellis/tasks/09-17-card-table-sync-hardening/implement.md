# 实施计划

1. 为 Python 同步工具建立结果对象、标准退出码、带请求标识的 UTF-8 结果文件、原子文件写入和受控备份基础设施。
2. 在导入路径接入全表预检：表头、标识唯一性、枚举、数值、资源路径和引用校验。
3. 将 `.tres` 属性读写限定到 `[resource]` 段，并让导入操作仅在预检通过后批量写入。
4. 让导出路径传播 CSV/XLSX 写入失败和真实 pending 文件结果。
5. 重构 Godot 编辑器插件为打开表格与确认后的安全同步两个入口，并从带请求标识的 UTF-8 结果文件处理结构化状态、解释器回退和成功后的资源扫描；首次打开时展示一次操作顺序，每次同步时明确提示方向、覆盖与 XLSX 锁定风险。
6. 更新 README、Git 忽略项和回归测试；执行 Python 静态检查与测试，以及适用的 Godot 检查。

## 风险与检查点

- `export_current_cards.py` 既要兼容现有 CSV/XLSX，也不能在校验失败后提前写资源；每一步用临时目录/夹具测试。
- `.tres` 结构可有多个子资源，属性替换必须基于 `[resource]` 边界。
- Windows 上 Python 启动方式不同；优先 `py -3` 并在失败时回退。
- 完成前核对变更只限插件、同步脚本、README、忽略项和对应测试。
