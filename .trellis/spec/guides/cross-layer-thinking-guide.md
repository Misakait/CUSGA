# Cross-Layer Thinking Guide

Godot 项目的主要边界是资源、Model、Controller、View、场景和 autoload。大多数运行时问题发生在这些边界之间，而不是单个函数内部。

## 实施前

### 1. 画出数据流

```text
输入 → Controller → Model/Resource → 信号 → View/场景
```

对每条箭头确认：数据类型是什么、谁负责校验、节点是否已经入树、资源是否可为空、失败如何返回。

### 2. 找到边界

| 边界 | 常见问题 |
|---|---|
| `.tres` → Resource | 脚本路径、字段名或默认值不兼容 |
| Resource → Model | 空资源、错误类型、重复随机或副作用 |
| Controller → Model | 输入未校验、重复扣除、取消后仍执行 |
| Model → View | 漏信号、同步信号错过、View 读到旧缓存 |
| 场景 → 脚本 | NodePath、唯一名、autoload 或生命周期错误 |

### 3. 固定契约

为每个公开方法写清输入、输出、失败原因和信号时序。动态协议统一使用字段名/方法名常量，并在调用前进行能力检查。

## 常见错误

- 只检查 `.tscn` 文本，不在运行时验证导出路径。
- 业务逻辑放在按钮回调，导致短按、取消或重复信号产生副作用。
- 在 `await` 之后才连接可能同步发射的信号。
- 以 `:=` 接收 `Variant`，让静态分析器推导出错误类型。
- 释放节点后忘记从类型化数组或场景缓存移除。
- 让 View 自己决定随机结果、消耗时间或扣除库存。

## 检查清单

- [ ] 已找到所有脚本、场景、资源和 autoload 引用。
- [ ] Model、View、Controller 的职责没有互相泄漏。
- [ ] 空值、失效节点、重复连接和取消路径都有处理。
- [ ] 资源身份、字段名和数组顺序在往返后保持不变。
- [ ] 已运行聚焦 Godot 测试和目标场景冒烟测试。
- [ ] 已检查运行日志和最终 `git status`。
