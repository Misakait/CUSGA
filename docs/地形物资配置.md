# 地形物资配置

地图房间根节点的 `terrain_profile` 决定房间初次生成哪些资源点。配置使用专属资源类型，新增资源时选择对应类型，不需要给普通 `Resource` 手动挂脚本。

## 类型与用途

| 配置位置 | 资源类型 | 用途 |
| --- | --- | --- |
| 房间根节点 → Terrain Profile | `RoomTerrainProfile` | 整个房间的物资池、数量和摆放范围 |
| Terrain Pool 的每个元素 | `terrain_pool_entry` | 一个候选资源点及其抽取权重 |
| 池条目 → Terrain Data | `TerrainCardData` | 资源点名称、图片、描述和交互行为 |
| 地形 → Interaction Behavior | `GatheringInteraction` | 一次性采集，完成后移除资源点 |
| 地形 → Interaction Behavior | `ReusableGatheringInteraction` | 多次采集，耗尽后按游戏时间恢复次数 |
| 地形 → Interaction Behavior | `FarmingInteraction` | 打开农场交互 |
| 地形 → Interaction Behavior | `VaultInteraction` | 进入宝库交互 |
| 地形 → Interaction Behavior | `BossInteraction` | 触发首领遭遇 |
| 采集行为 → Drop Table | `LootTableData` | 采集时获得物品的掉落表 |
| 掉落表 → Drops 的每个元素 | `LootDrop` | 单种物品、掉落概率和数量范围 |
| 掉落条目 → Item | `ItemData` 及其派生物品 | 实际获得的背包物品，通常拖入已有物品文件 |
| 房间配置 → Encounter Variance Range | `MonsterStatMultiplierRange` | 资源点遭遇怪物的属性倍率范围，与掉落数量无关 |

## 在 normal_terrain 中新增浆果丛

1. 在 Godot 文件系统打开 `resources/map/terrain/normal_terrain.tres`。
2. 展开 `Terrain Pool`，点击“添加元素”。新位置为空时，打开该元素右侧资源槽的下拉菜单，选择“新建 terrain_pool_entry”。添加元素负责增加位置，创建资源负责填入这个位置。
3. 展开新条目，在 `Terrain Data` 的资源槽选择“新建 TerrainCardData”。将 `CardId` 设为唯一标识，如 `berry_bush`；`CardName` 设为“浆果丛”，并设置 `CardIcon`。
4. 在 `Interaction Behavior` 选择 `GatheringInteraction` 或 `ReusableGatheringInteraction`，分别对应一次性采集与耗尽后再生。
5. 在采集行为的 `Drop Table` 新建 `LootTableData`。展开 `Drops`，添加元素并新建 `LootDrop`。
6. 将 `items/items/berry.tres` 拖到掉落条目的 `Item`。例如设置 `DropChance = 100`、`MinAmount = 1`、`MaxAmount = 3`，表示基础掉落概率为 100%，数量为 1～3 个。
7. 回到池条目的 `Weight`，设置浆果丛的相对抽取权重，保存资源。

`Terrain Pool` 应放 `terrain_pool_entry`，不能直接放背包物品、`TerrainCardData` 或整个 `RoomTerrainProfile`。用户单独保存的 `resources/map/TerrainTres/berry.tres` 是池条目，需要展开它的 `Terrain Data` 配置资源点；它与 `items/items/berry.tres` 这个背包物品不同。

## 新建掉落表时报 Cannot get class LootTable

掉落表的当前类型名是 **LootTableData**，在 `Drop Table` 中应选择“新建 LootTableData”。`LootTable` 仍是怪物配置的字段名，不能用它创建资源。

如果改名时已经展开采集行为，检查器可能保留旧的 `LootTable` 创建菜单。切换检查器选中对象，再回到原来正在编辑的同一资源，展开 `Terrain Data → Interaction Behavior → Drop Table`，让编辑器重建资源选择器。切换检查器选择不会修改资源字段；保留现有资源对象及未保存配置，避免用重新加载磁盘文件或替换整条资源链来刷新菜单。

重新打开后应显示“新建 LootTableData”。如果仍显示旧名字，需要检查脚本扫描和注册状态，不能反复点击旧选项。

## 数量、概率与位置

`MinCount` 和 `MaxCount` 控制房间所有资源点的合计数量，默认分别为 **1** 和 **3**，包含上下界，并且不会超过 `GridColumns × GridRows` 个格子。默认网格为 **6 列 × 4 行**。摆放区域为房间局部坐标 `PlacementMin = (360, 220)` 到 `PlacementMax = (920, 560)`，生成器把资源点放在随机选中的网格中心。

每个资源点独立按候选条目的 `Weight` 抽取类型，可以重复抽到同一种资源。树木和浆果丛的权重分别为 **3** 与 **1** 时，每次选取约有 **75%** 的概率选树木、**25%** 选浆果丛；不保证每个房间都同时出现两种。默认权重为 **1.0**，正常候选应使用正数。

`Drops` 的每一条独立判定，可能一次获得多种物品。`DropChance` 单位是 **百分比，范围 0～100**，默认 **100**；数量包含上下界，默认最少和最多各 **1**，并叠加装备提供的额外产量。

## 可重复采集

| 字段 | 脚本默认值 | 作用 |
| --- | --- | --- |
| TimeCost | 20 游戏时间点数 | 每次采集基础耗时 |
| GatheringTag | 空 | 匹配装备产量、工具减耗和采集遭遇；树木模板为 wood |
| MaxHarvestCount | 1 次 | 每轮可以完成的采集次数 |
| RefreshTimeCost | 100 游戏时间点数 | 次数耗尽后需要经过的游戏时间 |
| MinimumTimeCost | 1 游戏时间点数 | 工具减免后的最低采集消耗 |
| EffectiveToolSlot | 5 | 提供工具减耗的装备槽位编号 |

采集次数保存在每个资源点实例上。最后一次采集完成时，记录 `恢复时间 = 当前游戏累计时间 + RefreshTimeCost`。到期检查时恢复完整的 `MaxHarvestCount`，保留原资源点位置。刷新时间不是现实秒数，站着等待不会替代游戏时间推进。

`resources/map/terrain/reusable_wood_terrain.tres` 是完整的房间配置模板：每棵树可以采集 **3 次**，耗尽后经过 **80 点游戏时间**恢复；基础采集消耗 **20 点**，工具减免后最低 **5 点**；每次基础掉落 **1～3 根树枝**。该模板目前没有直接挂到生产地图场景。

## normal_terrain 当前内容与共享规则

当前配置的有效候选是 `CardId = wood`、`CardName = 树枝地形`，图片为 `res/environment/tree.png`，使用 `GatheringInteraction`，基础采集耗时 **20 点游戏时间**，100% 基础掉落 **1～3 根树枝**。一次性采集完成后资源点移除，返回房间不会重新长出。

多个普通群系房间共用 `normal_terrain.tres`，包括普通森林和清澈溪流。修改它会影响所有引用它的地图；只想改某一个房间时，先复制配置并给目标房间根节点重新分配。复制现有条目后修改嵌套资源时，确认地形数据、交互行为和掉落表也独立，避免连带修改共享内容。

房间首次进入活动窗口时才生成初始布局，并在本局仓库中保存。已经生成的房间重新进入会恢复原记录，因此新增候选应在新局或尚未生成的房间验证。地面掉落与资源点分别保存；配置物资池是在地图上生成可交互资源点，采集后才按掉落表生成可拾取物品。
