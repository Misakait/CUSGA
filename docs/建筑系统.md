# 建筑系统

## 玩家操作

1. 打开合成界面，用 **3 个树枝 + 1 个火**合成 **1 张篝火牌**。配方使用现有采集/合成链的树枝资源，以及商店已有的火资源。
2. 在玩家背包里**左键点击物品**弹出操作菜单，建筑牌提供**放置**选项；选择后背包收起并进入放置模式。仅打开菜单不发出放置请求，不扣牌。绿色占地表示可以放置，红色表示当前落点无效。
3. 在角色附近的当前房间地面**左键确认**，成功才消耗 **1 张建筑牌**。**右键或 Esc** 取消，取消不扣牌、不消耗行动值。放置本身没有额外行动值成本。
4. 靠近建筑后出现名称、动作、消耗/效果提示，按 **F** 使用最近一栋建筑。一次按下只触发一次，系统忽略键盘长按的重复事件。
5. 靠近建筑后，把鼠标放在建筑占地内并**持续按住左键 1 秒**，圆环填满后拆除鼠标指向的建筑。篝火在原地掉落 **1 个树枝**，点击掉落卡拾取；拆除不返还篝火牌、不恢复其它配方材料，也不额外消耗行动值。

篝火每次有效使用消耗 **50 点行动值**，恢复 **最多 200 点生命值**。生命值按角色当前上限钳制；例如只缺 50 点生命时恢复 50，仍消耗完整的 50 点行动值。**满血也可以休息**，实际恢复量为 0，仍消耗 50 点行动值并推进时间。死亡、目标太远、被墙挡住、战斗、过场、暂停、背包/合成/仓库打开时，不会产生篝火扣费或回血。篝火可重复使用，目前没有燃料、次数、天气熄灭或烹饪规则。

建筑使用为 **F 单次按下即时结算**，拆除为**左键持续长按**。拆除与地形采集复用同一个进度圆环，但拆除时长独立于行动值，不套用“行动值 / 10”的换算。开始建筑放置、使用或拆除，会取消尚未完成的旧鼠标长按，避免两种局外交互同时结算。

拆除过程中松开左键、移开鼠标、切换目标、走出范围、出现遮挡、按右键或 Esc、窗口失焦、暂停、打开模态界面、进入战斗或切换房间都会取消进度，不移除建筑、不生成掉落。持续按住不会连续拆除第二栋；必须重新按下。拆除完成时重新校验当前状态，旧回调或重复请求不能重复发放掉落。

物品菜单在普通左键松开后弹出，保留拖拽以及 Shift/Alt 快捷键。背包中的普通非建筑物品显示“暂无可用操作”；关闭菜单不改变库存。背包隐藏或库存变化时关闭弹窗；选择“放置”时再次校验槽位和物品身份，避免旧菜单使用已移动或消耗的牌。右键物品不再触发放置。

## 数值与放置边界

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| Footprint | 64 × 64 世界像素 | 中心对齐的建筑占地，默认图标在其中等比缩放 |
| InteractionRadius | 120 世界像素 | 角色中心到建筑中心的最大交互距离 |
| PlacementRadius | 220 世界像素 | 角色到放置中心的最大距离 |
| ActionPointCost | 篝火为 50 | 成功后调用 TimeSystem.PassTime，不是战斗能量扣减 |
| HealAmount | 篝火为 200 | 最大单次回血量，使用 HealthComponent.Add 通知 HUD |
| Destructible | true | 是否允许玩家长按拆除，剧情建筑可关闭 |
| DemolitionHoldSeconds | 1.0 秒 | 持续按住的真实时长，与行动值无关 |
| DestructionLoot | 篝火为 100% 掉落 1 个树枝 | 生产 LootTable 资源；空值表示无掉落；不应用采集产量加成 |
| PlayerClearance | 20 世界像素 | 最小角色脚下保护区，另会检查角色的真实碰撞形状 |
| ObstacleMask | 32，第 6 层 | 地图障碍层，与角色碰撞掩码一致 |
| FeedbackSeconds | 2.5 秒 | 一次结果提示的显示时长 |

放置必须让**完整占地**位于当前房间范围内；房间尺寸从 MapWorldModel.room_size 读取，当前为 1280 × 720。不允许覆盖既有建筑、可见棋盘卡牌、角色实际碰撞体或地面障碍。鼠标落点先使用画布坐标转换得到世界位置，再转换为房间局部位置，避免相机移动后建筑漂移。

## 职责与扩展接口

| 文件 | 职责与公开接口 |
| --- | --- |
| resources/buildings/building_data.gd | 继承物品数据，增加 Interaction、占地、距离、可选 WorldScene、拆除开关/时长/掉落；IsBuildingCard() 校验建筑配置，CanDemolish() 校验拆除配置 |
| resources/buildings/building_interaction.gd | 策略基类，提供 get_prompt()、get_unavailable_reason(context, state)、execute(context, state) |
| resources/buildings/rest_building_interaction.gd | 通用生命回复策略；篝火只是该策略的一份配置 |
| core/building/building_service.gd | 落点规则、扣除一张库存牌、同步交互结算；TryDemolish(room, instance_id, store) 按实例原子移除并返回掉落；重入保护 |
| core/building/room_building_store.gd | 按房间保存独立建筑记录；GetBuildings、AddBuilding、RemoveBuilding、BuildingsChanged |
| core/building/building_controller.gd | 背包请求、输入、距离/物理检查、使用/拆除目标选择、取消校验、棋盘掉落转发和房间表现生命周期 |
| core/building/building_view.gd | 建筑图标、预览、目标高亮和实体碰撞；不操作库存或生命值 |
| core/application/gameplay_port.gd | RequestPlaceBuilding(item) → BuildingPlacementRequested(item)，保持背包与地图系统解耦 |
| core/ui/inventory_ui.gd / slot_ui.gd | 普通左键菜单、拖拽与快捷键互斥、选择放置时重新校验库存 |
| core/gameflow/world_hold_interaction_controller.gd | begin_hold 沿用行动值换算；begin_timed_hold(owner, seconds, callback, target) 提供真实秒数长按；共用唯一活动状态与圆环 |

context 提供 health、inventory、player、gameplay_port；制作台策略可以通过 gameplay_port 请求打开制作界面，无需查找场景路径。state 是**每栋建筑独立**的字典，可存燃料、使用次数、制作队列等状态。get_unavailable_reason 必须无副作用，返回空字符串表示可执行；execute 必须同步返回含 success: bool、message: String 的字典，可附带 healed 等结果字段。失败不得修改玩家或实例状态。

**策略不得自行推进时间。** BuildingService 在执行前固定 ActionPointCost，只有 success=true 时才调用一次 PassTime。效果同步触发的生命/时间信号不能重入同一服务。长时制作应在同步效果中登记队列，再由独立组件推进，不能在 execute 中直接 await。

新增建筑步骤：

1. 创建使用 building_data.gd 的物品资源，设置名称、图标、占地、距离和交互策略。
2. 回复生命的建筑复用 rest_building_interaction.gd；制作台等另建继承 building_interaction.gd 的策略。
3. 需要专属外观时配置 WorldScene，场景根脚本继承 building_view.gd，保留 Icon: Sprite2D、Body: StaticBody2D 和 Body/CollisionShape2D。Configure(data, preview) 与 SetFocused(bool) 是表现协议。
4. 建立标准 crafting_recipe.gd 配方，登记到角色 CraftingComponent.RecipeBook，即可复用制作界面、库存、预览与 F 交互，无需给服务添加建筑 ID 分支。
5. 配置 Destructible、DemolitionHoldSeconds 和 DestructionLoot。掉落表使用 resources/loot/loot_table.gd，条目使用 loot_drop.gd，指定 Item、DropChance、MinAmount、MaxAmount。篝火固定为配方同源树枝、100% 概率、数量范围 1–1。服务生成标准 ItemStack，控制器经 BoardController.SpawnLootCards 生成可拾取卡，不直接写入背包。

TryDemolish 仅接受仍存在于指定房间的实例标识；成功结果包含 success、message、drops、position（房间局部坐标）。同步锁覆盖掉落生成与仓库移除，记录在发放前删除，防止信号回调或重复完成事件复制材料。后续耐久归零也可复用此结算入口；输入时长、鼠标命中和可达性检查属于控制器。

## 状态生命周期

建筑记录结构为 {id, data, position, state}：position 是房间局部坐标，data 是只读共享配置，state 由该实例独占。地图视图只保留当前窗口中的房间节点，仓库独立挂在 Main/RuntimeState 下，因而房间卸载、返回房间、进入/退出战斗都不会丢失本局建筑。建筑表现放在 BoardController/BuildingsRoot，不会被棋盘的 ClearAllCards 删除。

建筑随本局 Main 生命周期保存；**退出本局或重启游戏不会恢复建筑**。当前随机地图没有整局恢复协议，因此不能把旧地图坐标单独写进跨局存档。以后接入整局保存时，应连同地图身份、物品资源标识、房间局部坐标和实例状态一起序列化，不能把运行时节点作为存档来源。

RemoveBuilding(room, id) 仅删除指定建筑，不自动返还牌。玩家拆除通过 TryDemolish 组合删除与掉落，已拆除建筑不会在返回房间时重建。掉落卡沿用当前棋盘掉落的生命周期和拾取规则。每个实例状态独立，禁止把燃料或队列写到共用的 BuildingData/交互 Resource 上。

## 回归与手动验收

在已打开项目的 Godot 编辑器中打开 tests/godot/building_system_tests.tscn，按 **F6** 可运行自包含回归场景，不依赖编辑器 MCP。测试覆盖实际配方产出、材料不足、放置扣牌、越界/重叠/地形阻挡、房间隔离、实例独立状态、200 回复/50 消耗、封顶、满血正常收费和死亡拒绝、可替换策略、最近建筑、F 重复事件、世界/界面门禁、距离、取消及重新进入房间。菜单回归覆盖左键选择后放置、右键无效、拖拽与 Shift/Alt、库存失效；拆除回归覆盖生产圆环完成与取消、移开鼠标、走远、暂停、切房间、地面掉落一树枝、无额外行动值、重复回调防护及已拆建筑不复活。

主场景验收：获取树枝和火 → 合成篝火 → 背包左键点击，选择“放置” → 验证合法/非法预览与取消 → 放置 → 受伤和满血时分别靠近按 F，均检查 50 点时间消耗 → 验证长按中途松开/移开/走远/开背包均取消 → 完整长按 1 秒，检查篝火消失且原地出现一个树枝 → 点击拾取 → 离开房间再返回，已拆篝火不恢复。另验证拖拽物品和 Shift/Alt 未被菜单阻断，战斗或界面打开时不能使用或拆除建筑。检查输出窗口没有脚本或资源加载错误；测试结束只停止游戏，保留编辑器。
