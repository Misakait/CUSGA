# UI 动态过渡

## 当前效果与范围

房间／生态切换另使用独立的 `RoomArrivalBanner`：房间名以 28 像素字号显示在高度 24% 处，跨生态时在更上方的高度 10% 处另显示 48 像素生态名。两条提示各自以淡入、8 像素上浮、细线展开与淡出衔接，普通换房不会打断生态提示。行动值与文字动效在 `resources/map/room_transition_config.tres` 调整，触发规则、参数及复用方式见 [房间切换与地点提示](房间切换与地点提示.md)。这不经过下述 `UITransition` 的页面打开关闭流程。

主菜单、局外仓库与商店、局内背包与合成、大地图、暂停菜单及其参数设置页按用途采用轻微等比缩放、短距离滑入或纯淡入。入场一次平稳到位，退场快速淡出，不再反复拉伸、压扁或来回回弹。动画只作用于界面表现，不改变库存、金币、合成、建筑、地图探索或结算规则。

共享实现是独立组件 `core/ui/transitions/ui_transition.gd`（`class_name UITransition`），同目录的 `ui_transition.tscn` 可直接拖入新界面。它是普通 `Node`，不需要 Autoload，也不依赖 CUSGA 的库存、导航或暂停系统。宿主负责显示、隐藏、导航、业务输入与暂停状态；组件只负责位置、比例、透明度、临时鼠标遮罩和动画完成回调。现有七个界面控制器已引用新路径；`core/ui/ui_jelly_transition.gd` 保留原 UID，作为只继承新组件的旧路径兼容入口。

## 在新界面中复用

完整示例见 [组件 README](../core/ui/transitions/README.md)。将 `ui_transition.tscn` 拖到界面场景树，在检查器设置 `target_paths`（相对于组件的路径，例如同级面板为 `../Panel`）及 `motion_style`，即可通过 `play_open()`、`play_close(completed)` 播放。目标支持 `Control` 与 `Node2D`，不能重复选择，也不能同时包含父节点和它的子节点。

检查器的 `scale_strength` 默认 `0.02`，`open_duration` 默认 `0.22 秒`，`target_stagger` 默认 `0 秒`，`motion_style` 默认 `SOFT_SCALE`。组件入树时自动解析非空目标路径；代码在入树前调用 `setup()` 的配置优先。运行中更改检查器字段后，调用 `configure_from_inspector() -> bool` 重新应用；有效时重置旧动画并返回 `true`，路径缺失、目标类型错误、重复或父子重叠时返回 `false`、给出警告并保留上一份有效配置。

宿主先显示面板，再调用 `play_open()`；关闭时使用 `play_close(panel.hide)`，等退场完成再隐藏。组件不自动显示或隐藏面板，也不替宿主决定暂停。复制到其它 Godot 4.7.1 项目时，可整目录复制到相同的 `core/ui/transitions/` 路径；更换路径应通过 Godot 文件系统面板移动，让组件场景的脚本引用同步更新。

局外三个页面之间采用「旧页退场 → 原有场景生命周期切换 → 新页入场」。`SceneManager` 不为这条导航额外播放全屏黑幕。探索与战斗之间的 `ScreenTransitions` 黑幕继续使用原有参数，与这套界面过渡分开管理。

## 参数与动效样式

`setup(targets, strength = 0.02, duration = 0.22, stagger = 0.0, style = MotionStyle.SOFT_SCALE)` 配置动画。第五个参数为可选的 `MotionStyle`，前四个参数位置不变。`strength` 只控制 `SOFT_SCALE` 的等比缩放幅度，限制在 `0～0.04`；`duration` 不小于 `0.10 秒`；`stagger` 不小于 `0 秒`。现有界面继续使用脚本调用，新界面也可使用上述检查器字段，均不写入存档。关闭时长统一读取组件的 `CLOSE_DURATION = 0.14 秒`，关闭不采用错峰。

打开总时长为 `duration + stagger × max(目标数量 - 1, 0)`，首次开始还需要等待布局完成。下表的 `s` 为该界面的 `strength`，缩放是相对于目标原始缩放的倍率；位移为视口坐标单位，在项目基准视口中对应像素。

| 样式 | 全新打开的初值 | 打开的终值 | 关闭的终值 |
| --- | --- | --- | --- |
| `SOFT_SCALE` | X、Y 同为 `1 - s`，位移 `(0, 0)` | 原始比例，位移 `(0, 0)` | X、Y 同为 `1 - s / 2`，位移 `(0, 0)` |
| `RISE` | 原始比例，位移 `(0, 12)` | 原始比例，位移 `(0, 0)` | 原始比例，位移 `(0, 6)` |
| `SLIDE` | 原始比例，位移 `(16, 0)` | 原始比例，位移 `(0, 0)` | 原始比例，位移 `(8, 0)` |
| `FADE` | 原始比例，位移 `(0, 0)` | 原始比例，位移 `(0, 0)` | 原始比例，位移 `(0, 0)` |

所有样式全新打开时透明度倍率从 `0` 到 `1`，关闭从当前倍率到 `0`。反向请求从当前比例、位移与透明度接续，不重新套用全新打开的初值。`SOFT_SCALE` 不做非等比拉伸，也不放大超过基准：背包打开 `0.98→1`、关闭到 `0.99`；设置页打开 `0.985→1`、关闭到 `0.9925`。关闭完成的同一回调内恢复基准属性，再由宿主隐藏或移出场景树，避免缓存实例留下缩放和透明度残值。

打开使用 `1 - (1 - t)^3` 三次缓出，关闭使用 `smoothstep(0, 1, t)`，其中 `t` 为 `0～1` 的归一化进度。每次请求只朝目标属性平稳推进，不插入反方向的中间关键帧。

暂停菜单的背景遮罩单独淡入 `0.16 秒`，淡出与 `CLOSE_DURATION` 同步为 `0.14 秒`，最终颜色仍是场景原值 `Color(0, 0, 0, 0.55)`。透明鼠标遮罩位于临时 `CanvasLayer(1000)`，只在动画或等待布局期间接收鼠标；它没有可见色块，结束、重置或离树时隐藏。

## 使用入口与生命周期

共享助手的公开入口：

- `setup(targets, strength, duration, stagger, style)`：登记独立目标、时长和样式；后四项均有默认值，配置前会重置旧动画。
- `configure_from_inspector() -> bool`：重新解析检查器目标和参数；失败不覆盖上次有效配置。
- `play_open(completed = Callable())`：宿主先显示视图，再请求入场；可选回调在本次请求仍有效且完成时执行。
- `play_close(completed = Callable())`：宿主在回调中隐藏视图或完成换场，不在调用后立即隐藏。
- `reset()`：取消动画、等待布局的旧请求及旧完成回调，并恢复原始位置、缩放和颜色。
- `is_open_requested()`：读取最新目标状态；退出动画中界面仍可见，快捷键不能只检查 `visible`。
- `is_animating()`：包括等待布局与播放阶段，用于阻止此时的交易、使用物品、拖动和标记操作。

局外三页统一提供 `play_ui_enter(completed)`、`play_ui_exit(completed)`。`SceneManager` 在准备好目标资源后锁定本轮导航，等待旧页退出，再依原协议调用 `exit()`、移出旧实例、挂入目标、调用 `init()` 和入场入口，最后解除切换锁。新的导航点击在该轮结束前被忽略。加载失败时保留原页面并恢复其可操作状态。

主菜单的 `_ready()` 延迟请求首次入场；如果 `SceneManager` 已经请求入场，标记会跳过这次延迟请求。仓库和商店使用相同做法，不在每次内容刷新或重复 `init()` 时重播。缓存离树时调用 `reset()`；再次进入重新采集完成布局后的基准，避免叠加缩放。开始游戏也先让菜单退出，再沿用原 `change_scene_to_file(Main)` 入口。

背包的 HUD/快捷键、合成的 `GameplayPort` 请求和大地图的 `open_map` 动作仍沿用原入口。背包的「合成」按钮在背包退场完成后才请求打开合成；建筑放置操作也在退场完成后交给既有建筑入口。关闭背包立即清掉选中提示和物品菜单，关闭合成立即清掉提示，动画不延后这些临时状态的清理。

## 快速切换、输入与暂停

同向重复打开不重播；若提供新的完成回调，正在播放时只保留最新回调。反向请求取消旧 Tween，并从当前形变继续，旧回调因请求序号变化而失效。背包、合成和大地图的切换依据目标打开状态，支持退出中重新打开。局外页面导航采用串行切换；登录设置和暂停设置页之间采用先退后进，页间切换时禁止重复确认。

动画期间共享遮罩阻止鼠标点击落到下层，控制器继续负责键盘与业务入口的检查：局外页面不接受此时的交易、升级、拖放或重复导航；地图不接受此时的添加/删除标记；背包与合成的业务动作只在展开且动画结束后可用。遮罩不负责决定暂停，也不替代组件自己的数据校验。

助手以 `PROCESS_MODE_ALWAYS` 处理，Tween 使用 `TWEEN_PAUSE_PROCESS` 并忽略时间倍率，因此打开地图或暂停菜单后仍能播完。背包与合成不因这套动效额外暂停游戏。

大地图和暂停菜单在首次打开时记录之前的暂停状态；暂停占有期一直持续到退出动画完成。退出期间立即重开沿用同一份记录，不能把本界面造成的暂停误记成外部暂停。两者加入仅供这两类界面使用的 `ui_pause_owners` 节点组，以 `take_pause_release_ownership() -> bool` 交接「最后一个界面退出后恢复游戏」的责任，没有增加全局暂停管理器或 Autoload。

退出或离树时，界面先清除自己的占有标志。如果本来由它负责恢复游戏，就先检查结算是否接管；未接管时询问组内其它界面。仍展开或仍在退场的界面返回 `true`，把自己的 `_was_paused_before_open` 改为 `false` 并接手恢复责任；交出方保持游戏暂停。只有没有其它占有者接手时，才实际解除暂停。因此无论地图先关还是暂停菜单先关、两个退出动画是否交叠，都应等待最后一个界面退场。

如果最初暂停来自天赋等外部系统，两者都不会凭空获得恢复责任，全部关闭后仍保持原暂停；两者检测到结算已接管时也不解除暂停。该节点组目前只协调大地图与暂停菜单，不扩展到其它业务系统。参数设置与暂停菜单之间切页一直保留暂停。死亡与主动结束入口沿用原结算接管流程，取消未完成的动效，不等待视觉动画再处理结算。

## 布局约束

助手不重排节点，不修改 `pivot_offset`、锚点、容器、图集、字体或原始静态尺寸。发生缩放时，单个 `Control` 围绕自己的中心，多个目标围绕共同视口中心；其余样式保持原始比例。每个目标的原始 `position`、`scale` 和 `modulate` 均参与恢复，不能把恢复值写死为零位置、单位缩放或纯白。

首次动画先暂时隐藏目标颜色，等待容器完成布局后再采集位置，避免把尚未排版的坐标当成基准。新增接入时应选不被父 `Container` 直接重设位置的承载层；不要同时让原有动画和助手驱动同一目标的 `position`、`scale`、`modulate`。大地图不要直接把 `WorldMapCanvas` 加入目标，否则会与玩家拖拽缩放争用属性。
