# 游戏机制与玩法内容

## 局外交互长按确认

所有会消耗行动值的局外交互统一采用长按确认：地图方向移动、一次性采集、可重复采集、耕种、宝库和首领等目标在鼠标左键按下后只会开始进度，圆环填满时才进入原有业务逻辑。掉落拾取等行动值消耗为 `0` 的交互保持单击即时响应。战斗卡牌、战斗设置和其他不属于局外地图的输入不受此规则影响。

行动值与真实按住时长严格按 `长按秒数 = 实际行动值 / 10` 换算，不设置额外的最短或最长时长。当前地图移动默认消耗 `10` 点行动值，因此需要长按 `1.0` 秒；地形交互的默认 `TimeCost` 为 `20`，因此默认需要长按 `2.0` 秒。可重复采集会在按下时读取工具减免后的实际耗时并固定本次结果：例如实际消耗降至 `6` 点时，长按为 `0.6` 秒，完成时也只扣除这同一 `6` 点；其最小实际耗时仍由资源的 `MinimumTimeCost` 决定，默认不低于 `1` 点即 `0.1` 秒。

长按过程中，HUD 会以可见交互目标的右下角为锚点，默认额外偏移为 `0px, 0px`，绘制一个半径 `16px`、线宽 `6px` 的圆形进度条；圆心落在角点时约有四分之一圆环位于目标内、四分之三位于目标外。地图方向移动使用方向按钮精灵，地形交互使用地形卡图标，因此圆环会跟随目标而不再跟随鼠标。圆环从正上方顺时针增长，轨道颜色为 `Color(0.08, 0.10, 0.14, 0.72)`，完成颜色为 `Color(0.35, 0.95, 0.60, 0.96)`。该圆环只提供输入反馈，不会遮挡鼠标事件、扣除行动值或独立执行交互。

提前松开鼠标、拖出目标后松开、按下另一项局外交互、目标失效或场景卸载都会取消当前进度，立即隐藏圆环，并且不会消耗行动值、生成掉落、触发遭遇或切换场景。局外同一时刻只允许一个长按请求；进度完成前所有原有交互结果均不会发生。地图移动开始后会锁定重复移动，直到驻守战斗、过场与新场景加载的既有流程结束。

## 背包与合成界面入口

背包界面标题栏提供"合成"按钮，点击后收起背包并打开合成界面。两个界面彼此不持有引用，只通过 `GameplayPort` 的消息总线通信：背包仅发出"打开合成"的请求，合成界面自行完成绑定与刷新。

合成界面原有的打开方式（快捷键 `Tab`）保持不变，且仍为**切换**语义——再按一次即关闭。标题栏按钮则为**打开**语义，不会因为合成界面已处于可见状态而把它关掉。两处最终都汇聚到同一个打开流程。

背包与合成界面同为 `CenterOverlay` 的子节点，同时可见会互相重叠，因此按钮触发时会先收起背包。合成界面本身展示配方、材料持有量与合成数量，材料消耗与产出规则不变。

本机制未新增或调整任何数值：不涉及伤害、能量、冷却、概率或配方成本，仅新增一个界面入口与一条消息请求。

## 开局流程与带入消耗

每局游戏开始时，玩家角色与背包会被初始化为**确定状态**：背包内容严格等于玩家在仓库「带入栏」里选定的物品，不多也不少。执行这件事的唯一入口是挂在 `scenes/Main.tscn` 上的 `RunStartInitializer`（`core/gameflow/run_start_initializer.gd`），它排在 `Player` 节点之后，因此同级 `_ready` 触发时玩家的背包组件必定已就绪；初始化同步完成，随后广播 `RunStartInitialized` 信号，供后续开局环节（例如开局技能卡抽取）挂接，而不必各自监听场景加载。

带入栏的**权威状态**存放在 `ItemsControl`（Autoload）里，是一个固定 10 格的位置化数组，索引即栏位序号，空栏位用空条目表示。仓库界面（`scripts/warehouse/warehouse_control.gd`）的 `_carry_items` 只是这份权威的**视图**：每次刷新都由权威重建，放入与取出也先写权威再刷新视图。之所以不再让界面自己长期持有带入栏内容，是因为仓库场景实例会被 `SceneManager` 长期缓存复用——内容留在场景实例上时，开局带入之后无法从 `Main` 侧把它清空，玩家退回主菜单再进仓库就会重新看到已经带进游戏的物品，形成同一批物品的重复带入。

带入是**消耗**语义：初始化调用 `TakeCarryItems()` 取出全部待带入条目时，带入栏立即清空，无论背包是否装得下。因此同一批物品只会在某一局被带入一次；背包放不下的部分不会退回带入栏，而是留在背包之外并给出警告，让「背包容量小于所选带入量」这个问题能被发现，而不是无声销毁物品。带入栏为空时开局就是空手，不会被任何物品兜底填充。

调试用的开局配置节点 `DebugLoadoutSeeder` 在 `Main.tscn` 中默认停用（`Enabled = false`）。它原先会在 `call_deferred` 里覆盖背包，从而抹掉按带入栏初始化的结果；现在它是**手动工具**——需要直接进关卡调试时在检查器里临时打开，打开即表示有意覆盖开局带入。旧版把带入逻辑写在地图控制器 `map_control.gd` 里的实现已移除：地图控制器不再读取带入栏，也不再访问玩家私有背包字段。

## 开局技能卡抽取

每局在角色与背包初始化完成之后，立刻触发一次技能卡抽取：玩家从随机 5 张候选卡中选 2 张，选中的卡进入背包。抽取界面是挂在 `Main/UI/HUDLayer/HUDRoot` 下的 `SkillCardDraftScreen`（`scenes/ui_scenes/skill_card_draft_screen.tscn`），逻辑在 `core/gameflow/run_start_skill_card_draft.gd`；触发时机关联的是初始化节点广播的 `RunStartInitialized` 信号。

**为什么要额外做一次「补偿检查」**：抽取界面挂在 `UI` 之下，而 `UI` 在 `Main.tscn` 里排在 `RunStartInitializer` 之后，初始化节点的广播又是同步发出的——等抽取界面 `_ready()` 时信号早已错过，只写 `connect()` 会永远等不到开局。界面因此在订阅信号之后立即查询一次 `RunStartInitializer.HasInitialized()`，只要初始化已完成就补上本次抽取。这样正确性不再依赖「谁先谁后」的节点顺序：日后在 `Main.tscn` 里挪动界面位置，也不会让开局抽卡静默失效。每局只抽一次由内部状态保证，重复触发无效。

卡池来自 `res://resources/skill_cards/`（递归枚举），判定标准与出战卡组一致——看资源是否带 `Skill` 字段，而不是看脚本路径，因此新增卡数据不需要同步修改这里。候选从卡池中无放回地洗牌抽取，5 张互不重复。目录下的 `test_card_*` 属于测试资产，会被排除；当前生产卡共 62 张。已经持有的卡不会被排除，允许重复获得。

交互上，点击卡面即切换选中状态：选满 2 张后再点其它卡不会生效，再点一次已选中的卡则取消该选择；只有恰好选中 2 张时「确认」按钮才可用，因此不存在「选 1 张就确认」或「选 3 张」的中间状态。确认后选中的 2 张写入玩家背包 `Components/InventoryComponent`，未选中的 3 张直接丢弃，不会进入背包、也不会退回卡池。

**选中的卡只进背包，不自动进入出战卡组**：它需要玩家按既有流程自己从背包装进卡组，因此抽到的卡不会立刻出现在战斗手牌里。

抽取期间游戏会暂停（与暂停菜单使用同一个全局开关），确认后只归还本次造成的暂停——若打开抽取前游戏已因其它界面处于暂停，关闭后仍保持暂停。界面复用战斗卡面 `scenes/skill_card_scenes/SkillCard.tscn` 来展示卡名、元素、费用与描述；为此 `scripts/card_scripts/skill_card.gd` 的 `_ready()` 增加了父节点存在性守卫：只有父节点提供 `connect_card_signals` 时才连接（战斗中卡面的父节点恒为 `CardManager`，行为完全不变），使同一份卡面能安全地用在这个非战斗界面里。另外，卡面场景里的 `LockColor` 锁定遮罩**默认是可见的**（战斗侧由 `CardManager` 按控制锁状态解锁），因此抽取界面在挂载卡面后会显式调用卡面的 `unlock()` 把它解除，否则每张卡都会被一块半透明黑盖住、叠加全屏遮罩后近乎全黑。

## 局内暂停菜单

游戏中按下 `ESC`（输入动作 `pause_game`）或点击 HUD 右上角的「暂停」按钮，都会暂停游戏并弹出暂停菜单；两个入口完全等价，走同一段开关逻辑。暂停是全局的：局外探索与局内战斗共用同一个入口，因为暂停菜单挂在 `Main/UI/HUDLayer/HUDRoot` 下——局内战斗是把 `battle.tscn` 作为 `Main` 的子节点挂载的，所以这份浮层在两种状态下都存活，不需要在战斗场景里再挂一份。

菜单第一行是「继续游戏」，按下后收起菜单并恢复游戏；第二行是「退出游戏」，按下后立刻切回主菜单场景 `scenes/main_menu_scenes/main_menu.tscn`。「继续游戏」与「再按一次 `ESC`」完全等价，两者复用同一条关闭路径，因此暂停的归还判据只有一处实现，不会出现「继续」与「关闭」行为不一致。

暂停与恢复严格成对且不越权：菜单在打开前会记录当时的全局暂停状态，关闭时只归还「自己造成的那次暂停」。因此叠加到天赋选择界面（它使用同一个全局暂停开关）之上再关闭时，游戏会继续保持暂停，而不会把本该停住的界面放回运行。菜单被外部卸载（换场景、编辑器停跑）时也会兜底归还暂停，避免下一个场景带着 `paused = true` 启动、表现为整屏无响应。「退出游戏」按钮先解除暂停再切换场景，顺序不可颠倒。

暂停菜单的脚本只做三个映射：把「继续游戏」与「暂停/恢复」映射到 `get_tree().paused` 的开与关，把「退出游戏」映射为回主菜单。它不持有战斗、地图或天赋系统的引用，其余系统若也要暂停，继续各自使用既有的全局暂停开关。

**与战斗「设置」面板的避让**：战斗中右上角原本已有「设置」面板，其按钮占据 `x = 1150–1260px`，与新暂停键的 `x = 1176–1264px` 重叠。由于 HUD 位于 `CanvasLayer` 上，渲染与鼠标命中都在战斗 UI 之上，重叠会让该区域点击「设置」实际触发暂停。因此战斗侧面板整体左移：`offset_left` 由 `1010` 改为 `880`、`offset_right` 由 `1260` 改为 `1130`，按钮随之移到 `x = 1020–1130px`，两键之间保留 46px 间距。

布局数值：暂停键固定在视口右上角（锚定右侧），尺寸 `88 × 40px`，距右边缘 `16px`、距上边缘 `12px`；暂停时铺一层全屏遮罩，颜色为 `Color(0, 0, 0, 0.55)`；菜单面板由全屏 `CenterContainer` 居中，实测尺寸 `272 × 219px`（内边距 `36 / 24px`、行间距 `18px`），标题「已暂停」字号 `28`，两个选项按钮的最小尺寸均为 `200 × 48px`——在 `1280 × 720` 视口下「继续游戏」实测位于 `y = 331`、「退出游戏」位于 `y = 397`，两者相差一个按钮高度加一行间距。以上全部为纯 UI 表现参数，不涉及伤害、能量、冷却或概率数值。

## 战斗卡牌操作模式

战斗场景提供两种玩家卡牌操作模式：

- 点击：默认模式。玩家先点击手牌，已选卡牌会向上移动；再次点击同一张卡牌可取消整次选择。玩家可再点击一名敌人；再次点击同一敌人只取消敌人目标，卡牌保持选中。最后点击手牌区正上方的“确定”按钮施放。没有选择敌人时，只有自身目标牌与全体敌人、随机敌人、全体单位等自动目标牌可以点击“确定”：自身目标牌以玩家自身为目标，自动目标牌按卡牌固有范围展开；单体、任意单体与扩散牌必须先点击一名仍在场的敌人，未选中有效敌人时“确定”按钮保持禁用，无法对自己使用。“取消”、改选卡牌、切换模式或失去玩家回合时，卡牌会恢复正常手牌位置，且不消耗能量、不移除卡牌。
- 拖拽：玩家按住手牌时，真实卡牌保留在原手牌位置，屏幕中会出现内容相同、50% 不透明度且沿用既有拖拽缩放的虚影。虚影跟随鼠标并用于识别有效的敌人卡槽区域；单体和扩散牌在有效目标上松开后会将该敌人作为主目标，虚影立即消失，真实卡牌再从手牌区沿用既有飞行动画飞向该敌人施放。全体、随机、全体单位和自身等自动目标牌即使在敌人卡槽上松开，也只将其视为有效释放位置，不会记录或传递该单个敌人，因此不会形成单体飞行动画。无效位置或手牌区松开只会回收虚影，真实卡保留在手牌；自身目标卡仍可按既有手牌区外空白处释放规则使用。

操作模式属于玩家偏好，不是战斗数值或卡牌资源数据。首次运行、配置缺失或配置无法读取时，默认使用“点击”模式。玩家在战斗右上角的“设置”面板切换模式后，选择会写入 `user://settings.cfg` 的 `battle/operation_mode`，因此会跨战斗和游戏重启保留。

点击模式的“确定”按钮可用性由 `CardManager` 统一判定，`ClickModeActionBar` 只负责把结果映射为按钮的禁用状态：没有任何待确认卡牌，或卡牌需要显式敌人却没有选中在场敌人时禁用；自身与自动目标牌选中卡牌后即可确认。取消本次选择、切换操作模式和确认施放都会清除该禁用状态，避免它残留到下一次选卡。该调整未新增或修改任何伤害、能量消耗、冷却或概率数值。

## 目标与范围规则

点击模式仅把场上怪物的卡槽识别为显式敌人目标；拖拽模式同样只把虚影落点命中的怪物卡槽识别为显式敌人目标。单体、任意单体与扩散牌必须先指定一名仍在场的敌人才能施放：点击模式在未选中有效敌人时禁用“确定”按钮，确认入口也会拒绝整次施放，因此不扣除能量、不弃牌，更不会把玩家自身当成目标；已选中但随后离场的敌人同样失效，必须重新选择。自身目标牌的确认以玩家自身为目标；全体敌人、随机敌人、全体单位等自动目标牌不需要也不采纳单个敌人，仍由现有战斗结算逻辑按卡牌固有目标类型展开。其中随机敌人卡牌会在本次行动开始时从当前敌人中随机一次，并将该同一结果用于表现与效果结算。操作模式不改变卡牌效果、敌人 AI、伤害或任何战斗数值。

## 目标选择视觉反馈

当玩家点击选择或拖拽一张可用卡牌时，场上敌人怪物卡会根据该卡的目标类型显示局部视觉状态。拖拽期间由卡牌虚影跟随鼠标，真实手牌仍作为目标类型与最终行动节点的数据来源。该系统只影响卡面、名称、属性和状态栏，不缩放或变暗生命条；它不会修改目标合法性、选中顺序、随机结果、能量消耗或卡牌结算。

默认表现参数统一由 `CardManager` 的 Inspector 导出字段配置：怪物卡正常缩放为 `1.50`；可手动指定目标时，可选敌人在 `1.53` 与 `1.56` 之间循环呼吸，单程时长为 `0.25` 秒，完整放大缩小周期为 `0.50` 秒；鼠标悬停缩放为 `1.60`；主选中缩放为 `1.66`；次级选中缩放为 `1.60`；悬停已选中的次级目标时进一步放大至 `1.64`。主选中或自动选中目标显示宽度 `2px`、颜色 `Color(0.25, 1.00, 0.35, 1.00)` 的绿色边框；次级目标及其悬停状态同样为 `2px`，但使用更淡的 `Color(0.55, 1.00, 0.65, 0.80)`。不可选目标恢复 `1.50` 缩放，并以 `Color(0.45, 0.45, 0.45, 1.00)` 的颜色倍率变暗。静态状态切换继续使用 `0.08` 秒缩放过渡。

- 单体敌人和任意单体卡：所有在场敌人都是可选目标并呼吸；点击模式中鼠标悬停目标仅放大，点击后成为带绿色边框的主选中目标。确认前移到其他敌人时，已选目标继续保留绿色边框，鼠标下的其他敌人仍独立放大；拖拽模式中悬停合法目标即预览主选中状态。点击模式未选中任何敌人时不会把玩家自身当作缺省目标，也不显示玩家的时间轴高亮，同时“确定”按钮保持禁用；只有自身目标牌在没有敌人时才以玩家自身作为缺省预览目标。
- 扩散敌人卡：主目标采用主选中缩放和绿色边框；左右相邻敌人采用较小的次级选中缩放和浅绿色边框。确认主目标后，鼠标悬停已选中的次级目标不会移除浅绿色边框，并会进一步放大。
- 全体敌人、随机敌人与全体单位卡：所有受影响的敌人直接作为自动选中目标显示绿色边框，不播放呼吸动画。点击或拖拽模式都不会保存鼠标点击或释放点命中的单个敌人；行动队列只接收无显式敌人的目标，范围或随机结算继续由卡牌固有目标类型展开，因此自动目标牌不会错误飞向被点中或拖放到的敌人。随机敌人的实际结算目标仍按原规则在行动开始时随机一次。
- 自身目标卡：所有敌人怪物卡均变暗；玩家血量、能量和属性 UI 不新增目标边框、缩放或呼吸效果。

点击模式仍会拦截设置、确认、取消、结束回合等普通 GUI 控件，防止误操作；但怪物卡面内的名称、元素、`MonsterAttribute` 属性栏及其动态子控件会沿父节点识别为展示层并放行，因此在这些区域点击仍会命中同一只怪物的物理卡槽。

取消选择、改变操作模式、松开拖拽虚影、失去玩家回合或目标离场时，目标选择表现会被清理，所有怪物卡恢复正常颜色、无绿色边框且不再播放呼吸动画；任何非施放出口都会同时隐藏并回收虚影。

## 初始化测试卡池

战斗场景的初始化测试卡池固定为 21 张：`test_card_1` 至 `test_card_7` 各三张。总数高于 `DeckManager` 的 20 张最低补牌阈值，因此不会混入基础牌，抽牌与弃牌循环始终能覆盖全部目标类型。

- `test_card_1`：单体敌人；`test_card_2`：随机敌人；`test_card_3`：全体敌人；`test_card_4`：自身。
- `test_card_5`：任意单个单位，造成 10 点金属性物理伤害；`test_card_6`：全体单位，造成 5 点水属性物理伤害；`test_card_7`：扩散敌人，对主目标及左右相邻敌人各造成 12 点土属性物理伤害。
- 新增的 `test_card_5`、`test_card_6`、`test_card_7` 能量消耗均为 0；既有 `test_card_2` 与 `test_card_3` 分别保持 20 与 30 的消耗，其余既有测试牌保持原有配置。这些资源只用于战斗场景的测试牌池。

## 卡牌施放与命中反馈

向明确选中的场上怪物，或向本行动随机确定的场上怪物施放玩家卡牌时，卡牌会依次执行以下表现：

1. 脱离手牌布局并飞向目标怪物。
2. 按既有规则结算卡牌效果和每一段伤害。
3. 每次伤害完成后，由战斗反馈导演依据实际结果播放浮字、受力和必要的屏幕冲击。
4. 卡牌只在此后写入弃牌堆，再沿用既有弃牌渐隐并销毁。

受击反馈不再预判卡牌必定命中，而是在 `DamageReceiverComponent` 完成闪避、暴击、状态 Hook、护盾、伤害上限和生命扣除后，发出不可变的 `DamageResolutionResult`。因此玩家和敌人受到同一套反馈覆盖：闪避显示白色 `MISS`；普通伤害显示数值；暴击显示加粗、加大的深红数字；护盾吸收仅显示灰色数字；致死伤害不显示 `KO`，而是在数字下方绘制下划线。生命值实际恢复时显示绿色 `+数值`；状态施加、刷新和移除不再创建浮字。五行不再作为主要视觉识别，只保留现有伤害结算语义和资源颜色信息。

多段、扩散和全体伤害的每一段、每一个受影响目标都独立产生浮字反馈：不缩小字号，也不合并或跳过数字。段号用于把同一锚点的浮字做环绕空间分布，并按已加速的时长顺序入场；总段数会按 `1 / sqrt(总段数)` 缩短每段浮字时长，最低为单段时长的 35%，使高频数字更快离场且不会同时遮挡堆叠。局部目标受击动画按目标实例排入 FIFO，但同一多段序列只播放前三次。全局震屏按连续冲击批次最多播放前三次，超过上限的高频命中不再移动屏幕；它们仍保留自身浮字。为避免范围和高频伤害将短暂停顿串行累加为卡顿，同一连续全局冲击批次只由首个有效命中触发一次 Hit Stop。怪物生命归零后会立即从逻辑目标池移除并关闭鼠标拾取；反馈导演认领其死亡表现后，在渐隐结束时再释放卡面节点。因此死亡收尾不会让已经失效的怪物继续成为目标，也不会阻塞行动队列。怪物发起攻击时会先朝下方的玩家方向短促下冲并归位；这只是非阻塞表现，不改变攻击目标、伤害或行动队列。

## 战斗表现强度与果汁反馈

右上角“设置”面板新增“战斗表现强度”。选择会写入 `user://settings.cfg` 的 `battle/feedback_intensity`，跨战斗和重启保留；缺失或非法值回退为“完整”。该偏好不改变伤害、命中、回合、能量、状态或怪物 AI。

- 完整：每个有效命中都播放数值驱动的浮字；同一多段序列仅前三段播放目标受力，同一连续冲击批次仅前三次播放震屏、首个有效命中播放 Hit Stop。暴击、破盾、击杀在同一数值基础上附加可配置的语义强化。
- 减弱：保留所有结果浮字；目标受力与震屏沿用完整模式的前三次上限，震屏幅度降至完整模式的 40%，Hit Stop 均为零。
- 不限制每个目标或整个战场同时显示的浮字数量；每一段结算都会保留独立浮字，多段数字会按总段数加速并在播放结束后回收到对象池。

默认表现配方由 `CombatFeedbackProfile` 集中配置。每次伤害、护盾吸收或治疗的绝对数值先通过 `1 - exp(-数值 / 20)` 映射为连续饱和强度，再叠加 0.18 的最小可读强度；数值越高，浮字、受力、震屏与 Hit Stop 越强，但永不无限增长。单段普通浮字缩放为 `1.00–1.34`、上升距离为 `34–56px`、时长为 `0.24–0.42 秒`；多段浮字时长按总段数的平方根倒数缩短，最低为单段时长的 35%，同一目标按这些加速后的时长逐段显示。暴击和击杀可将缩放分别乘以 `1.18`、`1.12`，最终不超过 `1.80`。目标受力为 `6–22px`、时长为 `0.10–0.20 秒`，含结果语义后不超过 `28px`，同一多段序列每个目标最多播放 3 次受击动画；完整模式震屏为 `2–14px`、时长为 `0.06–0.14 秒`，含结果语义后不超过 `18px`，同一连续冲击批次最多播放 3 次；Hit Stop 为 `0.012–0.055 秒`，含结果语义后不超过 `0.075 秒`，世界时间缩放为 `0.05`，每个连续批次只触发一次。怪物攻击向下冲刺 `30px`、总时长 `0.22 秒`。玩家的伤害与治疗浮字均从血量 UI 右侧锚点（默认坐标 `600, 415`）出现。

## 等级与经验系统

玩家拥有角色等级，显示在背包「属性」面板的第一行（其后依次为物攻、物防、法强、法抗、速度）。等级从 1 级起步、上限 50 级，采用线性经验曲线；经验达到阈值时自动升级，一次获得的大额经验可以连续升多级。

经验由全局等级系统 `PlayerLevel`（`core/progression/player_level.gd`，已注册为 Autoload）统一管理，对外提供三类接口：

- 获得经验：`AddExperience(amount)` 返回实际入账经验，非正数或已满级时返回 0。经验足够时自动结算升级，并逐级发出 `LevelChanged`。
- 升级：`TryLevelUp()` 消耗当前经验提升一级；`AddLevels(count)` 直接提升指定级数、不消耗经验，供剧情推进或道具奖励使用。
- 查询与领取：`GetLevel()`、`GetExperience()`、`GetExperienceToNextLevel()`、`IsMaxLevel()`、`ClaimPendingAttributePoints()`。

**等级本身不直接修改属性数值**，而是每提升一级发放 3 点属性点。属性点由玩家实体在收到 `AttributePointsGranted` 信号后领取并写入玩家 `AttributeComponent` 的可用点数，再由玩家通过既有的属性点分配机制自行决定投入到哪一项属性。因此等级成长的实际效果取决于玩家的分配选择，而不是由等级自动决定。

当玩家实体尚未出现时（例如仍停留在主菜单），已经发放的属性点不会丢失，而是挂起在等级系统中；玩家进入场景时会自动补领全部挂起点数。

### 属性点分配界面

属性点通过背包「属性」面板的加点入口消耗：**只要还有未分配的点数，等级行右侧就会出现「分配」按钮；点数用完后按钮自动隐藏**（数据源是 `AttributeComponent.AvailablePoints`，由 `AvailablePointsChanged` 驱动实时显隐）。

点击「分配」打开加点弹窗（`scenes/inventory/AttributeAllocationPopup.tscn`）。弹窗按物攻、物防、法强、法抗、速度各占一行：属性名后回显该属性**已投入的点数** `（x）`，有待分配点数时变为 `（x→y）`，让玩家看清这一行会被推到几点；同一行还显示该属性的**当前值**，并提供 `+1` 与 `-1` 两个按钮。界面上方显示「剩余可分配点数」，每次点 `+1` / `-1` 都实时变动。弹窗默认隐藏，只在玩家点击「分配」时出现。

加点采用**先累计、后确认**的两段式：

- 点 `+1` / `-1` 只改动弹窗内部的待分配计数，属性组件此时**完全不被触碰**——可用点数与属性值都保持不变。已累计的行会把当前值显示为 `当前值 → 加点后值`，让玩家看清这一点加下去的实际收益。
- 累计总量以剩余可用点数为上限，达到上限时所有 `+1` 按钮禁用。
- 点「确认」才真正写入：按属性各调用一次 `TryAllocatePoint(类型, 累计数)` 一次性投入，随后关闭弹窗并清空累计。
- 点「取消」或直接关闭窗口都放弃本次累计，不写入任何点数。因此玩家可以反复调整再落笔，不存在点错就无法挽回的情况。

弹窗只调用属性组件的既有接口（`AvailablePoints`、`TryAllocatePoint`、`GetEffectiveValue`、`GetAttribute`），不直接改写属性字段，也不自行计算属性规则；每点成长值仅用于显示预计值。

**当前不接入任何玩法发放经验**：击败怪物、采集、垂钓等行为都不会提供经验值。本系统只提供数值骨架与接口，由后续玩法逐个调用。

## 数值记录

本机制未新增或调整伤害、能量、冷却或概率数值。多段浮字的时长倍率按 `1 / sqrt(总段数)` 计算，最低为 `0.35`，每段按加速后时长顺序入场；同一多段序列每个目标最多播放 `3` 次受击动画，同一连续冲击批次最多播放 `3` 次震屏且只触发 `1` 次 Hit Stop。`CardManager.card_drag_ghost_opacity` 的默认值为 `0.5`，即虚影为 50% 不透明度；虚影缩放继续使用已有 `card_drag_scale`，未新增缩放数值。选中上移距离和动画时长仅为 `CardManager` 可调的表现参数；战斗反馈的浮字、震屏、Hit Stop 与怪物下冲数值均见“战斗表现强度与果汁反馈”一节。

局内暂停菜单同样不涉及伤害、能量、冷却或概率数值：暂停键固定为右上角 `88 × 40px`（距右边缘 `16px`、距上边缘 `12px`），遮罩为 `Color(0, 0, 0, 0.55)`，菜单面板实测 `272 × 219px`，「继续游戏」与「退出游戏」两个按钮的最小尺寸均为 `200 × 48px`；战斗「设置」面板按钮左移至 `x = 1020–1130px` 以避免与新暂停键重叠。这些都是 UI 布局与表现参数，不影响任何战斗结算。
