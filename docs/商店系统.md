# 局外商店

## 入口与职责

局外商店入口是 `scenes/Shop/ShopNew.tscn`。仓库通过 `GlobalEventBus.scene_requested("shop")` 进入，商店返回按钮请求 `warehouse`。`core/autoloads/SceneManager.gd` 缓存场景实例，进入调用 `init()`，离开调用 `exit()`；旧 `scenes/Shop/Shop.tscn` 保留兼容。

`core/ui/shop/` 的控制器负责列表、详情、输入与刷新，交易规则仍由 `core/shop/shop_trade_bridge.gd` 和 `core/shop/shop_service.gd` 提供。库存权威为 GlobalWarehouse，金币为 PlayerWallet，升级为 PlayerProgression。界面不保存另一份长期库存，也不自行写存档。

| 文件 | 职责 |
| --- | --- |
| `core/ui/shop/shop_new_controller.gd` | 场景生命周期、组件订阅、整理升级和导航协调 |
| `core/ui/shop/shop_list_controller.gd` | 一处网格的格子创建、复用、内容和选中刷新 |
| `core/ui/shop/shop_item_slot.gd` | item_slot2 的名称、图标、数量/价格显示及点击、拖动意图 |
| `core/ui/shop/shop_buy_controller.gd` | 商品详情、购买数量和购买提交 |
| `core/ui/shop/shop_sell_controller.gd` | 待售来源、数量、提示和出售提交 |
| `core/ui/shop/shop_sell_icon.gd` | 图标接收拖放，区分拖放释放与独立点击 |
| `core/ui/shop/shop_source_slot.gd` | 一次出售使用的来源槽位快照与库存协议适配 |

## 购买

1. 点击右侧商品格，只更新 `Shop/BuyArea` 的图标、名称、单价和描述。
2. 在 `Shop/BuyArea/BuyCount/SpinBox` 选择数量。
3. 点击 `Shop/BuyArea/Buy/BuyButton` 提交购买。

点击商品格会在 `TooltipLayer/TooltipPanel` 显示与 WarehouseNew 相同的名称和描述详情框。点击左侧仓库格也会显示该物品详情，但只改变仓库格选中状态，不清除 BuyArea 当前商品。右键点击 `Shop/BuyArea/ItemIcon` 会清除购买区图标、名称、价格、描述和数量。

购买数量必须是正整数。余额和仓库容量同时满足时，扣除单价乘以数量的金币，并把全部物品加入仓库。余额或空间不足时整笔失败，不能部分成交。商品目录为无限库存；选择商品和修改数量均不购买。

## 出售

1. 从左侧仓库格拖动实际持有的物品，放入 `Shop/SellArea/ItemIcon`。
2. 拖入只设置待售物品和单价；更换待售图标和修改 `Shop/SellArea/SpinBox` 均不出售。
3. 点击待售图标，才按出售 SpinBox 的数量提交出售。

右键点击 `Shop/SellArea/ItemIcon` 会清除待售来源、图标、售价和数量，不会触发出售。

数量为 0 时，`Shop/SellArea/ScrollContainer/Notice` 显示“请选择数量”，物品和金币不变。拖动结束时的鼠标释放不算点击出售，必须另行点击图标。空物品、不可出售物品、数量不足或来源失效时给出提示，整笔失败。

待售状态绑定拖入的来源槽位及其物品、数量和洗炼属性快照。提交时重新检查，避免拖动期间仓库变化后误卖其它物品。出售只扣该格的物品，不能从其它同类装备格子补足数量。部分出售保留来源格的剩余数量及洗炼属性；来源被替换、整理或离开商店后，旧待售内容不能再次提交。

## 列表、升级与刷新

- 仓库使用 `ItemSection/ScrollContainer/SlotGrid`，展示全部已购容量；商品使用 `Shop/ScrollContainer` 内的网格，展示既有商品目录。
- 格子使用 `scenes/ui/item_slot2.tscn` 的 normal、hover、pressed 样式。商店空格保持禁用，禁用样式复用该场景的 normal，避免回退成默认灰色按钮。仓库格显示数量，商品格显示单价。
- 整理调用 GlobalWarehouse 的名称排序；升级由 PlayerProgression 校验并扣费，按钮显示真实费用，满级或余额不足时禁用。
- 库存、金币或升级变化刷新现有节点；容量不变时复用格子。缓存重入重新订阅并刷新，离开解除外部信号、清除选中与待售状态。
- 装饰文字不拦截点击，SpinBox 保留用户自定义主题及输入功能。

## 数值与配置来源

| 项目 | 当前值、单位和条件 | 来源 |
| --- | --- | --- |
| 买卖数量输入 | 初始 0 件，最小 0 件，最大 100 件，步长 1 件；0 不成交 | ShopNew 的两处 SpinBox 使用 Godot 默认范围；以后可在场景中覆盖 |
| 买入单价 | 优先使用物品正数 BuyPrice；显式上架但没有自身价格时使用目录 DefaultBuyPrice，默认 100 金币/件 | `resources/item/item_data.gd`、`resources/shop/shop_catalog.gd`、Bridge.GetBuyPrice |
| 卖出单价 | 优先使用正数 SellPrice；否则 floor(解析后的买入单价 / 2)，无正数结果时不可售 | Bridge.GetSellPrice |
| 总价 | 单价 × 指定数量，单位金币；规则层拒绝总价 ≤ 0 或大于 2147483647 | ShopService 的总价校验 |
| 商品目录 | 显式 Goods 顺序优先；AlsoIncludeEveryPricedItem 默认为 false，开启后补入其余正买价物品并按 CardId 排序 | `resources/shop/shop_catalog.tres`、Bridge.BuildStockList |
| 新档金币 | 1200 金币；有效存档覆盖默认值，上限 2147483647 金币 | `core/autoloads/player_wallet.gd` 的 DefaultGold/MaxGold |
| 仓库容量 | 27 + 9 × 仓库等级，等级 0～3，即 27/36/45/54 格 | `core/progression/player_progression.gd` |
| 仓库升级费用 | 从 0/1/2 级升级分别花费 300/600/1000 金币 | PlayerProgression.WarehouseCosts |

商品的逐件价格读取当前 `.tres` 和目录资源，本次界面接入不修改商品名单或经济数值。金币、仓库及升级通过 SaveManager 原参与者协议持久化，格式不变。机制汇总见 [游戏机制与玩法内容](游戏机制与玩法内容.md)。

## 验证要求

通过已打开的 Godot 4.7.1 编辑器 MCP 扫描脚本，运行 `shop_new_contract` 聚焦套件及 ShopNew、WarehouseNew、主菜单和 Main 冒烟。真实输入应覆盖多件购买、拖入/更换图标/修改数量不交易、0 数量提示、图标点击出售和缓存重入。测试使用隔离数据，真实运行涉及存档时先备份、停止游戏后恢复；只停止游戏，保留编辑器。
