# 夜晚通道驻守怪物设计规格

## 背景

进入夜晚时，地图之间的通道有概率被怪物驻守。玩家点击被驻守的通道会先进入战斗，击败怪物后才能通过；失败则停留在原地图。

这个功能需要和后续地图生成策略解耦。地图生成以后可能不再由当前的 `scene_to_scene` 字典驱动，所以驻守系统不应直接依赖某个具体地图生成脚本的内部数据结构，而应依赖“可枚举当前地图通道”的接口或适配器。

## 已确认规则

### 生命周期

- 驻守怪物只在夜晚存在。
- 入夜时生成一张“驻守通道表”，决定本夜哪些通道被占领。
- 天亮时清空本夜所有驻守通道。
- 被击败的驻守通道在当前夜晚保持清空。
- 下一次入夜重新 roll，可能再次出现驻守怪物。

### 通道状态

- 通道状态按无向边记录。
- 如果 A-B 通道被驻守，那么 A 到 B、B 到 A 都视为被同一个通道状态阻挡。
- 玩家从任意方向击败驻守怪物后，这条无向通道在当前夜晚双向清空。

### 生成范围

- 默认每条相邻地图通道都可以独立 roll 驻守怪物，包括和 `home` 相关的通道。
- 如果玩家在入夜 roll 表时拥有指定天赋标签，则排除和 `home` 相关的通道。
- 这个标签只在入夜生成驻守表时检查一次。
- 该标签只由天赋系统授予，而天赋系统只在白天出现，所以不需要处理“夜晚中途获得标签导致规则变化”的情况。

### 驻守概率

- 驻守概率是全局固定的可配置值。
- 全局基础驻守概率放在独立的 `PassageGuardSettings` 资源中。
- 游戏运行中可以改变当前驻守概率。
- 如果玩家拥有指定天赋词条，入夜 roll 表时驻守概率可以按该天赋效果变化。
- 天赋词条的概率效果同时支持加减固定概率点和乘法倍率。
- 多个概率效果的结算顺序是先加法、后乘法：`final = clamp((base + additiveSum) * multiplierProduct, 0%, 100%)`。
- 最终概率需要 clamp 到 `0%..100%`，避免多个效果叠加后出现负数或超过必定触发的概率。
- 概率应在入夜生成驻守表时计算一次，避免同一夜晚内因为 UI 刷新或状态变化导致已生成表反复变化。

### 怪物确定时机

- 入夜时只决定“哪些通道被驻守”，不固定具体 `MonsterData`。
- 玩家进入某个地图场景后，系统根据当前场景的地图类型配置通道驻守怪物池。
- 当前场景内每个被驻守的通道按钮，会从当前场景对应的怪物池中确定本次显示和战斗使用的怪物数组。
- 这意味着同一条无向通道的占领状态是全局共享的，但怪物表现由玩家当前所在地图场景决定。

### 怪物池

- 每个地图类型单独配置通道驻守怪物池。
- 示例：森林通道刷木系怪物，雪地通道刷水系怪物。
- 怪物池配置放在 `map_attribute` 上，和 `scene_name`、`scene_count`、`scene_dir`、`scene_pkg` 同属于地图类型配置。
- 怪物池不硬编码在地图按钮脚本里。
- 怪物池的抽取单位是 encounter 组合。
- 每个 encounter 组合是一个 `Array<MonsterData>`，因此可以表达单怪或多怪战斗。
- 示例：森林池可以配置 `[木精]`、`[木精, 藤兽]`、`[古林树人]`，实际解析时随机抽取一个组合。
- 当前 `MonsterData` 只有名字，没有图标；按钮 UI 应先支持名字显示和缺省图标/占位表现，等 `MonsterData` 后续新增图标字段后再直接读取。

### UI 表现

- 如果按钮代表的通道没有驻守怪物，按钮保持正常地图移动按钮表现。
- 如果按钮代表的通道有驻守怪物，按钮显示即将刷出的怪物信息。
- 当前阶段至少显示怪物名字；未来 `MonsterData` 增加图标字段后，显示 `MonsterData.Icon` 和名字。
- 如果驻守 encounter 包含多个怪物，按钮显示多个怪物名字。
- 玩家点击该按钮时进入对应驻守怪物战斗。

### 移动与战斗结果

- 点击被驻守通道时，先进入战斗。
- 战斗胜利后自动移动到目标地图。
- 战斗失败后不移动，玩家留在当前地图。
- 战斗胜利会清除该无向通道在当前夜晚的驻守状态。

## 推荐架构

### `PassageGuardState`

负责保存当前夜晚被驻守的无向通道集合。

- 输入：可枚举通道的地图拓扑快照、玩家标签状态、入夜时计算出的驻守概率。
- 输出：某条无向通道是否被驻守。
- 不保存具体 `MonsterData`。
- 不依赖地图按钮、场景节点路径或具体地图生成脚本。

### `IPassageTopologyProvider`

负责把当前地图生成结果转换成稳定的通道列表。

- 当前实现可以适配现有 `scene_to_scene`。
- 后续地图生成策略重构时，只需要替换这个 provider 或适配器。
- 驻守状态系统只消费通道列表，不关心地图如何生成。

### `IHomeRoomClassifier`

负责判断某个地图节点是否是 `home`。

- 初版建议按地图类型名 `"home"` 判断，而不是按 `Vector2i(1,1)` 坐标判断。
- 当前代码里生成器会把 `map[1][1]` 写成 `"home"`，`MapTypes` 中也存在 `scene_name = "home"`；类型名比坐标更接近设计语义。
- 后续如果地图生成策略改成资源、tag、场景元数据或固定入口节点，只需要替换这个 classifier，不影响驻守状态、按钮渲染或战斗流程。

### `PassageGuardProbabilityProvider`

负责计算入夜时使用的驻守概率。

- 基础值来自独立的 `PassageGuardSettings` 资源。
- 运行中允许被游戏逻辑修改当前值。
- 允许读取玩家天赋词条并应用加法和乘法概率修正。
- 只给 `PassageGuardState` 提供入夜当刻的最终概率，不负责保存驻守表。

### `PassageGuardSettings`

负责保存通道驻守系统的全局可配置项。

- 初版至少包含基础驻守概率。
- 后续可以承载默认天赋 tag 名、概率上下限、调试开关等全局规则。
- 该资源不挂在 `TimeSystem` 或地图按钮上，避免时间系统和 UI 节点知道通道驻守玩法细节。

### `PassageGuardMonsterResolver`

负责在玩家进入某个地图场景后，为可见的被驻守通道解析要显示和战斗使用的怪物数组。

- 输入：当前地图场景或地图类型、通道方向/目标、当前夜晚状态。
- 输出：该按钮要显示和战斗使用的 `Array<MonsterData>`。
- 怪物池来自 `map_attribute` 的地图类型配置。
- 同一房间内同一个被驻守按钮的怪物数组在进入房间时固定。
- 离开房间后再次进入，可以重新根据当前地图类型随机解析怪物数组。
- 同一房间内 UI 刷新不能让同一个按钮从一组怪物变成另一组怪物，否则按钮显示和点击后的战斗内容会对不上。

### `GuardedPassageFlow`

负责拦截地图移动按钮点击。

- 如果通道未驻守，走原有地图移动流程。
- 如果通道已驻守，发起战斗。
- 战斗胜利后清除通道状态并继续执行原本的移动。
- 战斗失败后停止移动。

## 测试关注点

- 入夜生成驻守表，天亮清空。
- 每条相邻通道独立 roll。
- 无向通道双向共享驻守和清除状态。
- 拥有指定天赋标签时，入夜 roll 会排除 `home` 相关通道。
- 点击被驻守通道时，胜利才移动，失败不移动。
- 同一个地图类型使用自己的怪物池解析按钮显示怪物。
- 每个地图类型的驻守怪物池配置在 `map_attribute` 上。
- 驻守怪物池随机抽取 encounter 组合，战斗入口收到的是该组合的 `Array<MonsterData>`。
- 多怪 encounter 的按钮会显示多个怪物名字。
- 同一房间内重复刷新按钮不会改变已解析的驻守怪物数组。
- 运行中改变全局驻守概率会影响下一次入夜 roll。
- 天赋词条可以通过加减固定概率点和乘法倍率影响入夜时最终驻守概率。
- 多个概率效果按 `final = clamp((base + additiveSum) * multiplierProduct, 0%, 100%)` 结算。
- `home` 判断通过单独 classifier 完成，替换 classifier 不影响驻守状态核心逻辑。
- 更换通道拓扑 provider 不影响驻守状态核心逻辑。
